# 体素星球：方块在球面上「看起来不正」——业界方案调研

> 整理自项目讨论与公开资料，对照本项目当前实现（`main` 轴对齐球 / `feature/quad-sphere` 六扇区实验）。

---

## 1. 和你最像的起点：简单「距离球心」+ 轴对齐方块

**做法**：在一个 **世界轴对齐** 的体素格里，用 `半径 - 距离` 雕出球（`main` 分支 `VoxelWorld` 即如此）。

**代表**：[Blocky Planet（Bowerbyte）](https://www.bowerbyte.com/posts/blocky-planet/)

> 用「到中心距离」做球体很简单，但 **方块表面和重力方向对不齐**，在球上建「向上」、走路都会别扭。

**结论**：他们 **不认为** 只靠相机能修好，而是从 **数据结构** 下手。

---

## 2. 路线 A：仍要「方块感」—— Quad Sphere（六面体球）

**代表**：Blocky Planet、[Planetcraft](https://github.com/ddupont808/planetcraft)

| 做法 | 说明 |
|------|------|
| **六套网格** | 把球拆成立方体六个面，每面一套 **自己的方格坐标**，再投影到球面（quad sphere / cube-to-sphere） |
| **按扇区找邻居** | 方块「上下左右」相对 **本地重力**，不是世界 Y |
| **壳层 + Chunk** | 由里到外分层；Planetcraft 在高度上还会 **拉伸再细分** |
| **玩家** | 关 Unity 默认重力，自定义指向球心；用 **插值旋转** 对齐地面，避免在极点 snap 瞬转导致晕 |

Planetcraft 还强调：**不可能无失真地把平面贴到球上**；大星球（如 12km）海平面附近失真才小。

**对本项目**：要让方块相对 **本地上下** 更正，需重写坐标 / 邻居 / 生成（见 `feature/quad-sphere` 分支），不是调相机；工作量接近重做地形管线。

---

## 3. 路线 B：不要 Minecraft 方块——Marching Cubes 平滑球壳

**代表**：Planet Nomads、[Planet Tech / Voxel Planets](https://buckslice.github.io/planet-tech)、若干体素星球 Demo

| 做法 | 说明 |
|------|------|
| **3D 密度场 + Marching Cubes** | 表面是三角 Mesh，跟着球面弯，没有「世界轴对齐的方块顶面」 |
| **球面噪声** | 在球坐标或径向距离上采样 3D 噪声 |
| **LOD** | 八叉树 / 四叉树，远处降面 |
| **玩家** | 同样 **球心重力 + 表面对齐** |

[Unity Marching Cubes 文章](https://0x00000000.dev/terrain-generation/) 提到：密度用 **渐变** 而不是 0/1，表面会更滑、不像方块球。

**对本项目**：挖洞 / 存档逻辑要跟着改，但 **视觉上最不像「斜方块」**。

---

## 4. 路线 C：换「格子形状」—— 六边形 / 二十面体

**代表**：[Planet Smith 开发视频（5 年体素星球）](https://www.youtube.com/watch?v=-QL42dGHsmY)

| 做法 | 说明 |
|------|------|
| 从 **二十面体细分** 得到球（三角形 / 六边形为主） |
| **Hexels**（六边形体素）替代立方体 |
| **Mesh blocks** 做平滑过渡 |
| **体素物理** 直接查体素，不用 MeshCollider |

**目标**：站哪块地，块看起来都差不多，只有 12 个五边形例外。

**对本项目**：等于换一套体素系统，不是小改。

---

## 5. 玩家 / 相机：业界共性

Godot 论坛球面移动、[Voxanet](https://github.com/verlorengest/voxanet)、Blocky Planet 等共同点：

| 项目 | 常见做法 |
|------|----------|
| **重力** | 关默认重力，`up = normalize(位置 - 球心)` |
| **朝向** | **四元数** 对齐 up，避免欧拉角在极点翻车 |
| **旋转** | **平滑插值**，不要每帧硬 snap |
| **相机** | 跟 **本地 up** 走，**不是** 固定世界 Y 来让方块「正放」 |

也就是说：业界也是 **「人跟重力走」**，不是 **「相机跟方块网格走」**。

Blocky Planet 还提到：旋转用插值；早期用 snap 在部分区域 **很 disorienting**（令人晕眩）。

---

## 6. 对照表：问题 → 业界怎么办

| 你的现象 | 业界常见解法 |
|----------|----------------|
| 方块相对地平线斜 | Quad Sphere 六套网格；或 Marching Cubes；或 Hexels；或 **接受 + 超大半径** |
| 走路晕 / 世界在转 | 球心重力 + 四元数 + 平滑 up |
| 极点奇怪 | 避免欧拉角；六扇区比单网格好 |
| 球太小曲率明显 | Planetcraft 12km；Nomads 120km——**尺度很大** |
| 要可挖方块星球 | Blocky Planet / Planetcraft：**改结构**；Nomads：**平滑体素** |

## 7. 对本项目的实际含义

| 方案 | 分支 / 状态 | 特点 |
|------|-------------|------|
| **简单距离球 + 轴对齐** | `main` / `VoxelWorld` | Blocky Planet 所称 lackluster 档；实现简单，方块相对地平线会斜 |
| **Quad Sphere 六扇区** | `feature/quad-sphere` / `VoxelQuadSphereWorld` | 方块沿径向对齐；扇区边缘、存档等待完善 |
| **Marching Cubes** | 未做 | 视觉最平滑，改动大 |
| **Hexels** | 未做 | 大工程 |

**关于「只改相机」**：未查到成熟项目用「相机 Up = 世界 Y」在 **可绕球行走** 的同时又让 **轴对齐方块全局正放**。Blocky Planet 明确选择改 **方块怎么排**，而不是改相机骗眼睛。

---

## 8. 可选方向（按成本）

1. **接受 Minecraft 式方块球** + 调大 `Planet Radius`（成本最低）
2. **Quad Sphere 六扇区**（重写坐标 / 邻居 / 生成，中等～大工程）→ 见 [`QuadSphere分支说明.md`](QuadSphere分支说明.md)
3. **Marching Cubes 显示层**（体素存盘不变、只改 Mesh，中等工程）
4. **换 Hexels**（大工程，Planet Smith 路线）
