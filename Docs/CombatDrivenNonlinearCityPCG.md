# 战斗驱动的非线性城市 PCG 方案

## 1. 文档结论

本方案不再把“商业区、工业区、交通区、服务区”作为城市 PCG 的核心结构。
这些分类可以作为可选美术主题保留，也可以完全关闭；它们不再决定任务、路线、敌人或难度。

新的城市生成目标是：

> 任务只给玩家最终目的，战斗提出问题，空间提供多种解法，玩家通过结果理解空间用途。

本方案也不取消现有道路和建筑网格。网格继续承担对齐、地块、碰撞、连廊连接和稳定生成；
改变的是控制层级：战术机会和难度要求先生成，网格与建筑随后承载这些要求。

最终结构为：

```text
飞船物理能力与任务规则
        ↓
策划难度配置与战斗压力预算
        ↓
非线性战术机会网络
        ↓
道路/飞行通路/建筑网格
        ↓
建筑、连廊、可破坏结构和敌人入口
        ↓
行为仿真、体验验证和 Seed 拒绝
```

---

## 2. 设计目标

### 2.1 必须实现

1. 城市是开放、非线性的战术空间，而不是按区域顺序通关的走廊。
2. 玩家不需要看“恢复区”“遮挡区”等文字，也能通过空间形状、敌人行为和即时结果理解用途。
3. 同一个战斗问题至少提供两种有效解法，并具有不同风险、操作要求和收益。
4. 策划通过语义化参数控制难度，不需要理解底层建筑摆放算法。
5. PCG 难度必须同时受到飞船尺寸、速度、转弯、制动、推力和模块损伤的约束。
6. Boss、普通敌机、任务目标和出生入口必须消费同一套战术数据，不能只把城市当作视觉碰撞层。
7. 同 Seed、同版本、同配置必须生成稳定结果。
8. 不合格布局必须被验证器拒绝，而不是进入正式任务后再依赖玩家容错。

### 2.2 不作为核心目标

1. 不要求模拟真实城市功能分区。
2. 不要求完整道路交通逻辑。
3. 不要求商业、工业、住宅等城市学意义成立。
4. 不要求玩家遍历全部战术机会。
5. 不使用空气墙强迫玩家走唯一路线。
6. 不使用区域名称或大量 HUD 箭头解释玩法。
7. 不建立全局最优导航，让玩家仍能利用地形欺骗简单 AI。

## 3. 核心设计原则

### 3.1 区域是工具，不是步骤

旧思路：

```text
出生区 → 机动区 → 遮挡区 → 恢复区 → Boss 区
```

新思路：

```text
玩家受到远程压制
├─ 进入连续遮挡楼群，安全但绕远
├─ 高速穿过暴露大道，危险但更快
└─ 垂直换层，从高空重新取得攻击角度
```

区域不负责规定顺序，而是对不同玩家状态提供不同价值。

### 3.2 非线性不等于无结构

PCG 仍然必须设计：

- 哪些战术机会相邻。
- 玩家多快能发现它们。
- 每个机会解决什么问题。
- 使用机会需要付出什么代价。
- 使用成功后获得什么即时收益。
- 是否存在对所有状态都最优的支配性路线。

### 3.3 不通过文字教学，通过因果教学

玩家理解空间用途的过程应当是：

```text
看见空间承诺
→ 在压力下尝试
→ 系统规则立即产生结果
→ 玩家记住这种空间形态
```

例如玩家进入楼群后：

- 敌方锁定音中断。
- 弹丸打在建筑表面。
- 远程敌人需要重新寻找射线。
- 玩家从另一侧出现时获得侧翼角度。

这些结果比“进入遮挡区”文字更有效。

### 3.4 难度来自机会与压力的关系

难度不是单纯增加敌人血量或数量，而是共同控制：

- 玩家面临的问题强度。
- 可用解法数量。
- 解法距离。
- 操作精度要求。
- 路线可读性。
- 使用成功后的收益窗口。
- 连续高压后是否存在恢复机会。

## 4. 总体技术架构

### 4.1 第一层：物理能力包络

生成器必须从玩家和 Boss 的实际能力得到以下数据：

```csharp
public struct FlightCapabilityEnvelope
{
    public Bounds intactBounds;
    public Bounds damagedBounds;
    public float cruiseSpeed;
    public float maximumSpeed;
    public float lateralAcceleration;
    public float verticalAcceleration;
    public float brakingAcceleration;
    public float stableTurnRadius;
    public float damagedTurnRadius;
    public float reorientationSeconds;
}
```

关键物理约束：

```text
所需横向加速度 = 速度² / 转弯半径
制动距离 = 速度² / (2 × 有效制动加速度)
出口预览时间 = 出口首次可见距离 / 建议路线速度
```

PCG 不得生成理论有净空、但飞船按当前速度无法转过的路线。

### 4.2 第二层：战术属性场

将战场划分为空间采样单元。采样单元不是玩家可见的方格，而是供生成、AI 和验证使用的数据。

```csharp
public struct TacticalFieldSample
{
    public Vector3 position;
    public float cover;
    public float exposure;
    public float maneuverSpace;
    public float brakingSpace;
    public float verticalEscape;
    public float bossBlock;
    public float attackAngle;
    public float recoverySafety;
    public float destructionUtility;
    public float routeLegibility;
}
```

战术属性应尽量由实际几何计算，而不是只因为某个 Bounds 被命名为恢复区就得到高分。

示例：

- `cover`：多个主要威胁方向的射线被建筑遮断的比例。
- `exposure`：有效武器射程内无遮挡方向、可见敌方入口和连续视线长度。
- `maneuverSpace`：飞船包围盒按目标转弯半径扫掠后仍无碰撞的比例。
- `bossBlock`：玩家能通过而 Boss 当前真实包围盒不能通过的程度。
- `recoverySafety`：遮挡、无敌人入口、制动空间和逃生出口的组合结果。
- `destructionUtility`：可切割结构能否真实落向敌人/Boss 的概率和预计收益。

### 4.3 第三层：战术机会网络

从连续属性场中提取可被玩家利用的战术地点和连接关系。

```csharp
public sealed class TacticalOpportunity
{
    public string stableId;
    public TacticalOpportunityKind kind;
    public Bounds bounds;
    public Vector3[] entrances;
    public Vector3[] exits;
    public float utility;
    public float risk;
    public float executionDifficulty;
    public float legibility;
    public string[] connectedOpportunityIds;
}
```

```csharp
public enum TacticalOpportunityKind
{
    ManeuverBowl,
    OcclusionChain,
    ExposureShortcut,
    RecoveryPocket,
    KiteLoop,
    TacticalChoke,
    VerticalEscape,
    AttackPerch,
    DestructionAmbush
}
```

机会网络必须是多环、多出口结构，不是从起点到终点的一条链。

### 4.4 第四层：战斗压力与任务

任务系统只给目的，战斗压力负责让不同机会在不同时间具有价值。

```csharp
public sealed class CombatPressureSource
{
    public string stableId;
    public CombatPressureKind kind;
    public Vector3 origin;
    public float range;
    public float severity;
    public Vector3 preferredDirection;
}
```

压力类型包括：

- 远程射线压力。
- 近战追击压力。
- Boss 撞击压力。
- 多方向包围压力。
- 模块损伤后的控制压力。
- 任务目标暴露压力。

任务与敌人必须引用战术机会，而不是只引用世界坐标。

## 5. 保留网格，但改变网格的职责

### 5.1 继续保留

- 道路模数和路口对齐。
- 建筑地块采样。
- 建筑朝向。
- 连廊连接 Socket。
- 建筑碰撞代理。
- 城市分块和渲染批次。
- 同 Seed 稳定生成。

### 5.2 不再由网格决定

- 哪里是恢复机会。
- 玩家为什么进入某块空间。
- Boss 在哪里容易受阻。
- 敌人应该从哪个方向施压。
- 哪条路线是安全、快速或高操作路线。
- 当前任务的难度曲线。

### 5.3 推荐生成顺序

```text
任务与难度配置
→ 生成多环连接骨架
→ 分配战术机会配额
→ 在骨架上确定机会位置和相邻关系
→ 将骨架吸附/投影到道路网格
→ 局部合并、删除、错位或扩张网格
→ 生成飞行净空和建筑地块
→ 放置建筑、连廊和可破坏结构
→ 放置敌人入口、目标和 Boss 出生道路
→ 运行战术与物理验证
```

### 5.4 允许的局部网格变形

- 合并街区形成转向碗或恢复庭院。
- 删除一段直路形成视线阻断。
- 增加斜向捷径形成快速暴露路线。
- 将多个街区连成闭合风筝环。
- 抬高一段道路形成垂直换层。
- 在相邻建筑之间保证战术连廊净空。
- 用大型建筑切断全图贯通射线。

基础仍然是稳定网格，但战术意图拥有局部修改权。

## 6. 战术机会的生成契约

### 6.1 机动碗 `ManeuverBowl`

目标行为：转向、拉开距离、重新瞄准、上下换层。

生成约束：

- 有效直径不小于目标飞船稳定转向直径。
- 至少两个出口，出口方向差应足够明显。
- 不允许所有出口同时被一个远程射线覆盖。
- 内部可以有低矮遮挡，但不能产生看似能过、实际会撞的模糊缝隙。
- 玩家进入前能够预读至少一个出口。

体验验证：

- 玩家在区域内产生明显横向速度或角速度变化。
- 玩家能够完成一次转向后重新获得射击线。
- 中位停留时间符合预期，不因寻找出口显著超时。

### 6.2 连续遮挡链 `OcclusionChain`

目标行为：主动切断远程敌人的视线并从侧翼重新接敌。

生成约束：

- 由至少两次连续遮挡组成，不是单独一栋楼。
- 路线在遮挡之间保留可读的下一段轮廓。
- 进入后应在限定时间内中断主要远程威胁射线。
- 出口提供新的攻击角度或更安全的后续选择。
- 不生成只有入口没有有效出口的深口袋。

体验验证：

- 进入后锁定中断或敌方命中率明显下降。
- 玩家离开时与进入时的攻击角度有显著变化。
- 远程敌人不会无视真实遮挡继续精确射击。

### 6.3 暴露捷径 `ExposureShortcut`

目标行为：用风险换取时间、位置或输出效率。

生成约束：

- 相比安全路线至少缩短可感知的时间或距离。
- 入口可以看见目的方向和主要危险来源。
- 路线本身导航简单，不与高精度复杂转弯同时叠加。
- 必须存在中途退出或末端脱离空间。
- 不能成为速度、安全和攻击收益同时最优的支配性路线。

体验验证：

- 玩家选择该路线时平均速度更高。
- 玩家承担更长敌方视线暴露或更多射线压力。
- 成功通过后确实更快获得目标或攻击位置。

### 6.4 恢复口袋 `RecoveryPocket`

目标行为：减速、稳定姿态、自我修复、重新判断局势。

生成约束：

- 有足够制动距离和完整旋转空间。
- 至少遮挡两个主要威胁方向。
- 敌人入口不能正对区域内部。
- 至少两个撤离方向，避免被近战敌人永久封死。
- 必须位于高压空间可达范围内，而不是地图边缘的无关空地。
- 不提供脱离战斗规则的魔法无敌，仅通过真实几何和敌人入口规则产生安全性。

体验验证：

- 玩家进入后速度、角速度和连续受击率下降。
- 自我修复技能存在完成施放的真实时间窗口。
- 玩家能够看见至少一个后续战术选择。

### 6.5 风筝环 `KiteLoop`

目标行为：利用玩家与敌人/Boss 的体型和转弯差异进行追逐。

生成约束：

- 形成闭合或近似闭合的连续可飞路径。
- 内圈存在不能被大型 Boss 直接切穿的结构。
- 环路曲率符合玩家转向包络。
- 至少两个逃生出口。
- Boss 能追击但效率低于玩家，不能因为完全无法导航而静止。

体验验证：

- 玩家能够绕中心结构累计一定角度。
- Boss 的追击距离、转向误差或攻击精度发生可感知变化。
- 环路不能成为无限安全、无代价的永久逃跑路线。

### 6.6 战术窄口 `TacticalChoke`

目标行为：玩家穿过狭窄连廊结构，迫使大型 Boss 绕行或突破。

生成约束：

- 使用实际模型和碰撞体测量玩家净空。
- 玩家标准飞船可通过，当前 Boss 真实包围盒不可通过。
- 玩家在入口方向能够看见缝隙轮廓。
- 通过后有回身射击和再次逃离的空间。
- Boss 附近至少存在一条绕行路线或确认突破路径。
- 窄口不能紧邻玩家/Boss出生位置。

体验验证：

- 玩家成功穿越。
- Boss 真实受阻并进入绕行或突破行为。
- 玩家获得可量化但有上限的输出窗口。

### 6.7 破坏伏击点 `DestructionAmbush`

目标行为：玩家利用切割技能改变战场或伤害 Boss 模块。

生成约束：

- 可切结构的倒塌方向能够覆盖合理的 Boss 经过区域。
- 切割位置、支撑关系和坠落路径满足现有结构物理。
- 玩家存在观察、施放和撤离位置。
- 不要求像素级时机，不生成几乎不可能成功的摆设。
- 倒塌后不能永久封死所有路线。

体验验证：

- 建筑确实能被切割并继续参与后续结构破坏。
- 坠落结构只对真实碰撞到的 Boss 模块造成伤害。
- 成功使用后产生明确的结构、音效和模块反馈。

## 7. 非线性拓扑生成

### 7.1 推荐拓扑

每张城市地图至少包含：

- 一个不完全规则的外环或大环。
- 两到三条跨区连接。
- 一组低空遮挡网络。
- 一组中空连廊网络。
- 少量高空快速路线。
- 多个路线重新汇合点。

示意：

```text
                       [高空攻击位]
                      /             \
 [连续遮挡链]──[机动碗]──[暴露捷径]
       │             │             │
 [恢复口袋]──[任务/Boss空间]──[垂直逃生]
       │             │             │
 [战术窄口]────[风筝环]────[破坏伏击点]
```

图中没有强制顺序。连接关系只表示可达和战术转换。

### 7.2 拓扑约束

- 每个主要战术机会至少两个普通出口。
- 关键位置不得只有单一进出方向。
- 删除任意一个普通连接后，主要任务目标仍可到达。
- 从主要交战位置出发，应在配置的时间内到达至少两种战术解法。
- 不同解法应在安全、速度、操作和收益中至少有一项明确差异。
- 不允许一条路线在所有玩家状态下同时最优。
- 高空路线不能绕过全部战斗和任务压力。

### 7.3 机会与问题配对

```csharp
public struct TacticalProblemCoverage
{
    public CombatPressureKind problem;
    public string[] candidateOpportunityIds;
    public float minimumUtility;
    public float maximumReachSeconds;
}
```

验证器应检查：

```text
每个主要压力源
→ 是否至少存在两种可达解法
→ 解法是否具有不同代价
→ 解法是否仍受飞船当前损伤能力支持
```

## 8. 策划难度控制接口

### 8.1 不使用单一难度值直接生成

可以保留一个总难度档位，但总档位必须展开为多个语义维度。
这些配置必须由 Unity 编辑器内的策划 Tool 创建和修改；策划不直接编辑 C#、JSON、场景组件或裸 `ScriptableObject` Inspector。
Tool 在内部将界面配置保存为版本化的配置资产，运行时只读取已经确认并锁定的资产。

```csharp
[Serializable]
public sealed class CombatCityDifficultyProfile
{
    [Range(0f, 1f)] public float navigationChallenge;
    [Range(0f, 1f)] public float combatPressure;
    [Range(0f, 1f)] public float exposurePressure;
    [Range(0f, 1f)] public float recoveryGenerosity;
    [Range(0f, 1f)] public float tacticalOpportunityDensity;
    [Range(0f, 1f)] public float routeLegibility;
    [Range(0f, 1f)] public float bossPursuitPressure;
    [Range(0f, 1f)] public float destructionUtility;
    [Range(0f, 1f)] public float decisionComplexity;
}
```

### 8.2 参数到生成行为的映射

| 策划参数 | PCG 控制内容 |
|---|---|
| `navigationChallenge` | 净空余量、转弯数量、垂直落差、连续动作数量、制动余量 |
| `combatPressure` | 同时活跃敌人数、敌人入口方向数、敌人角色组合、交战持续时间 |
| `exposurePressure` | 连续可见时间、远程射线数量、掩体间距、开放路线长度 |
| `recoveryGenerosity` | 恢复机会数量、平均距离、面积、遮挡方向、敌人入口避让 |
| `tacticalOpportunityDensity` | 连廊、风筝环、遮挡链、垂直逃生和攻击位数量 |
| `routeLegibility` | 入口预览、地标可见度、轮廓连续性、出口视觉对比 |
| `bossPursuitPressure` | Boss 速度优势、绕行倾向、攻击精度、停火窗口、免疫时间 |
| `destructionUtility` | 可切割伏击点数量、倒塌命中容差、成功收益 |
| `decisionComplexity` | 同时可见选择数、路线差异、重新汇合距离、上下层切换 |

### 8.3 压力预算

每个局部战斗空间使用压力预算，禁止所有难点同时拉满。

```csharp
public struct LocalDifficultyBudget
{
    public float navigation;
    public float enemies;
    public float exposure;
    public float resourceDenial;
}
```

约束建议：

- 四项总和不得超过当前区域预算。
- 同一局部空间最多两项达到高档。
- 高导航压力空间降低同时远程射线数量。
- 高暴露压力空间降低路线操作复杂度。
- 长时间高战斗压力后必须提高附近恢复机会权重。

### 8.4 三类高难度模板

#### 操作型

```text
导航挑战：高
战斗压力：中
暴露压力：中
路线可读性：高
恢复慷慨度：中
```

玩家知道该去哪里，但必须准确驾驶。

#### 战术型

```text
导航挑战：中
战斗压力：高
决策复杂度：高
战术机会：多
路线可读性：中高
```

操作要求适中，但必须根据敌人和损伤选择正确解法。

#### 生存型

```text
暴露压力：高
恢复慷慨度：低
战斗压力：中高
导航挑战：中
```

强调模块保存、脱离视线和恢复时机。

### 8.5 六档星球难度建议

| 星球 | 主要新增要求 | PCG 倾向 |
|---:|---|---|
| 1 | 理解遮挡、开阔和恢复 | 解法多、入口明显、恢复近、操作宽容 |
| 2 | 学习上下换层 | 增加垂直逃生，仍保持高可读性 |
| 3 | 学习风险收益路线 | 暴露捷径和安全绕路差异增大 |
| 4 | 应对多方向压力 | 增加敌人方向，但不同时提高复杂驾驶 |
| 5 | 综合利用破坏和连廊 | 减少无条件安全机会，提高战术执行要求 |
| 6 | 综合决策与受损飞行 | 解法更少但不少于两种，恢复更远，Boss压力更高 |

## 9. 非文字化的空间表达

### 9.1 表达优先级

```text
空间几何
> 敌人行为
> 即时战斗结果
> 运动与粒子
> 声音
> 灯光与材质
> HUD 文字
```

HUD 只表达任务目标、Boss状态和必要战斗信息，不显示区域名称。

### 9.2 各机会的环境语言

| 战术机会 | 空间形状 | 敌人/系统反馈 | 辅助表现 |
|---|---|---|---|
| 遮挡链 | 错位高楼、连续转折、出口重新开阔 | 锁定中断、子弹命中建筑、敌人重新搜索 | 冷色、压缩构图、出口亮度提高 |
| 暴露捷径 | 笔直、开阔、目标可见、掩体稀少 | 远程射线和曳光弹明显 | 高亮路面、风声增强、远景清晰 |
| 恢复口袋 | 水平、宽阔、三面遮挡、多个出口 | 受击率降低、允许完整修复 | 稳定灯光、低频环境音、减少闪烁 |
| 风筝环 | 中央实体、外围连续环路 | Boss转向吃亏、距离逐渐拉开 | 环向灯带、重复但连续的轮廓 |
| 战术窄口 | 明确缝隙、玩家/Boss尺寸对比 | Boss受阻、停火、撞击或绕行 | 边缘灯、撞击火花、结构震动 |
| 破坏伏击 | 可读支撑、明确倒塌方向 | 切割后真实倒塌并伤害模块 | 切面、裂纹、结构声和尘埃 |

### 9.3 三次接触教学

1. **低风险展示**：第一次出现时压力较低，玩家容易偶然成功。
2. **明确收益**：第二次在真实压力下使用，系统给出强烈结果反馈。
3. **自由应用**：后续不再特殊照顾，由玩家主动寻找和组合机会。

该教学不要求线性关卡，只要求新手的初始邻域包含一组易读机会。

## 10. 任务系统接入

### 10.1 清理任务

问题：如果所有敌人都会飞到玩家面前，最优策略是原地等待，城市路径没有价值。

建议：

- 远程敌人占据战术位置，不无限追到玩家出生点。
- 近战敌人负责迫使玩家移动。
- 敌人入口分批激活，同一时刻只形成可理解的主要压力方向。
- 击杀目标可以保留，但敌人阵地和攻击角度必须与战术机会关联。
- 玩家推进是更有利的策略，而不是由空气墙强制。

### 10.2 设施突袭

- 多个目标允许任意顺序处理。
- 每个目标至少存在两种接近方式。
- 不同目标附近的主要压力类型不同。
- 目标摧毁后改变局部战术场，例如关闭远程炮塔、打开垂直通路或暴露新入口。

### 10.3 Boss 任务

任务只显示“击败模块化 Boss”。

城市提供：

- 开阔远程交火空间。
- 连续遮挡楼群。
- 风筝环。
- 战术连廊窄口。
- 自然恢复口袋。
- 可切割建筑伏击点。

Boss 行为必须服从：

- 开阔区远程射击更有效。
- 玩家躲入楼群后精度下降并尝试绕行。
- 只有玩家长期躲入无法撞击的夹缝时，Boss 才将撞楼作为逼出手段。
- 连廊位于追击直线上时可以突破；普通建筑不能成为默认通行方式。
- 喷气损坏影响速度、加速、摇晃和转向，但伪物理底线保证 Boss 保持飞行能力。
- 地形破坏、模块破坏和追击状态都应改变玩家当前最优选择。

## 11. 动态难度边界

动态难度不应在玩家眼前移动建筑、缩窄缝隙或生成墙体。

允许调整：

- 尚未生成或尚未激活的敌人入口。
- 后续敌人角色比例。
- 同时活跃压力方向数量。
- Boss 攻击窗口和行为权重的有限范围。
- 已生成的多个合法机会中，哪些获得更高战术价值。

不允许调整：

- 玩家已经看到的建筑位置。
- 当前正在穿越的净空。
- 已经建立因果预期的区域规则。
- 为克制玩家临时关闭其当前有效策略。

动态判断可以使用：

- 碰撞频率。
- 长时间迷航。
- 平均速度和刹停失败。
- 模块损失比例。
- 连续受击时间。
- 对战术机会的成功使用率。

必须使用平滑、滞后和冷却，避免系统每几秒反向针对玩家。

## 12. 自动验证与体验指标

### 12.1 物理可行性

- 完整玩家飞船可以通过主机会网络。
- 约 30% 机动能力损失的玩家仍有撤离与恢复路线。
- 严重偏推玩家至少能从主要交战空间退出。
- Boss 不能通过战术窄口，但拥有绕行或确认突破路径。
- 转弯所需加速度不超过目标能力包络。
- 恢复口袋满足制动距离和姿态恢复空间。

### 12.2 战术覆盖

- 每个主要压力至少两种有效解法。
- 从主要交战位置到最近解法的时间不超过配置上限。
- 关键战术机会至少两个出口。
- 不存在覆盖全图的单一远程射线。
- 不存在速度、安全、输出同时最优的支配性路线。

### 12.3 行为指纹

| 机会 | 预期玩家数据变化 |
|---|---|
| 机动碗 | 横向速度、角速度或垂直速度增加 |
| 遮挡链 | 敌人视线中断次数和持续时间增加 |
| 暴露捷径 | 平均速度和受火时间同时增加 |
| 恢复口袋 | 速度、角速度和连续受击率下降 |
| 风筝环 | 围绕中心累计角度增加，Boss跟随误差增加 |
| 战术窄口 | 玩家通过、Boss受阻、输出窗口出现 |
| 破坏伏击 | 切割成功、真实碰撞、Boss模块受损 |

如果不同机会中的玩家数据没有显著差异，说明这些机会只有名字不同，体验没有成立。

### 12.4 Seed 报告

建议报告至少包含：

```text
有效机会总数
各机会类型数量
平均可选解法数
最差位置可选解法数
最长连续暴露时间
最近恢复机会距离中位数
有效风筝环数量
有效Boss窄口数量
可用破坏伏击点数量
玩家/Boss可达图连通率
支配性路线检测结果
完整/受损玩家仿真通过率
稳定校验值
拒绝原因
```

## 13. Unity 策划工具

策划必须通过 Unity 编辑器内的专用 Tool 配置本系统，而不是直接打开生成器组件修改大量技术字段。

推荐入口：

```text
Unity 菜单
Tools
└─ Planet Combat
   └─ 战斗城市 PCG 策划工具
```

推荐窗口类型：

```csharp
public sealed class CombatCityPcgDesignerWindow : EditorWindow
```

Tool 是策划配置、候选生成、场景预览、难度比较、验证和发布的唯一正式入口。
底层 `ScriptableObject` 和生成器 Inspector 可以保留给程序调试，但不能作为策划日常工作流。

### 13.1 Tool 窗口布局

建议使用四区布局：

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶部：配置资产 / 任务 / 星球 / Seed / 生成 / 锁定 / 验证   │
├──────────────┬──────────────────────────┬───────────────────┤
│ 左侧配置面板 │ 中央场景预览             │ 右侧报告与警告    │
│              │                          │                   │
│ 难度滑杆     │ 城市、机会网络、热力图   │ 物理可行性        │
│ 机会配额     │ 玩家/Boss可达范围        │ 战术覆盖          │
│ 压力预算     │ 敌人射线、入口和目标     │ 支配性路线        │
│ 高级参数折叠 │                          │ Seed拒绝原因      │
├──────────────┴──────────────────────────┴───────────────────┤
│ 底部：候选 Seed 卡片 / 配置差异 / 隔离试玩 / 保存发布       │
└─────────────────────────────────────────────────────────────┘
```

中央区域优先复用 Unity `SceneView`、`Handles` 和 Gizmos，不单独制作一套脱离场景的渲染器。

### 13.2 Tool 内部配置资产

Tool 保存一个版本化的策划资产：

```csharp
[CreateAssetMenu]
public sealed class CombatCityPcgDesignProfile : ScriptableObject
{
    public int schemaVersion;
    public string profileId;
    public string displayName;

    public MissionPcgProfile clearance;
    public MissionPcgProfile assault;
    public MissionPcgProfile boss;

    public PlanetDifficultyBinding[] planetBindings;
    public int lockedSeed;
    public int lockedChecksum;
}
```

建议保存目录：

```text
Assets/Settings/CombatCityPCG/
├─ Profiles/           策划主配置
├─ Presets/            项目内置模板
├─ LockedSeeds/        已锁定Seed及校验值
└─ Reports/            可选的审计报告资产
```

策划不需要直接进入这些目录操作。Tool 负责：

- 新建配置。
- 从模板复制。
- 重命名和备注。
- Undo/Redo。
- 脏标记和保存。
- 配置版本迁移。
- 缺失字段补默认值。
- 锁定 Seed 和稳定校验值。

所有修改应走 `SerializedObject` / `SerializedProperty`，并接入 Unity Undo；不能在窗口关闭时静默丢失配置。

### 13.3 策划输入界面

基础页只显示策划语义，不显示底层公式：

- 任务类型。
- 星球难度档。
- 总体难度模板。
- 导航挑战。
- 战斗压力。
- 暴露压力。
- 恢复慷慨度。
- 战术机会密度。
- 路线可读性。
- Boss追击压力。
- 破坏收益。
- 决策复杂度。

机会页提供：

- 各机会的最小数量、目标数量和最大数量。
- 是否允许该任务生成某种机会。
- 两种机会之间是否允许相邻。
- 玩家发现机会的最大距离或时间。
- 每个主要问题最少需要几种解法。

压力页提供：

- 局部压力预算。
- 同时高压力维度上限。
- 敌人入口方向上限。
- 连续高压时间上限。
- 高压后恢复机会要求。

物理页默认只读显示：

- 玩家完整/受损包围盒。
- 玩家转弯直径。
- 玩家制动距离。
- Boss当前真实包围盒。
- 玩家可过而Boss不可过的净空范围。

物理值从正式飞船和Boss配置自动采集。只有程序/高级模式可以覆盖，避免策划输入与实际物理脱节。

### 13.4 难度模板与星球绑定

Tool 应内置可复制模板：

- 新手教学。
- 操作型。
- 战术型。
- 生存型。
- 普通Boss。
- 高难Boss。

星球页使用矩阵配置：

| 星球 | 清理任务模板 | 突袭任务模板 | Boss模板 | 难度倍率 | Seed策略 |
|---:|---|---|---|---:|---|
| 1 | 新手教学 | 新手教学 | 普通Boss | 0.00 | 固定或候选池 |
| 2 | 基础战术 | 基础战术 | 普通Boss | 0.20 | 候选池 |
| 3 | 战术型 | 战术型 | 普通Boss | 0.40 | 候选池 |
| 4 | 战术型 | 生存型 | 高难Boss | 0.60 | 候选池 |
| 5 | 生存型 | 生存型 | 高难Boss | 0.80 | 候选池 |
| 6 | 混合高难 | 混合高难 | 高难Boss | 1.00 | 锁定合格池 |

模板是起点，不是共享引用陷阱。策划选择“复制并调整”后生成独立配置，避免修改一个模板意外影响全部星球。

### 13.5 场景预览

点击“生成预览”后，Tool 在专用临时根节点下构建预览：

```text
__CombatCityPcgPreview_DoNotSave
```

预览规则：

- 默认不进入 Play Mode。
- 默认不修改当前场景已有对象。
- 再次生成前回收旧预览根节点。
- 预览对象设置为不写入正式场景的编辑器临时对象。
- 只有点击“烘焙到隔离测试场景”才创建可保存场景内容。
- 切换配置或Seed时明确提示未保存的配置变化。

SceneView 工具栏应允许切换：

- 最终美术。
- 战术机会节点和连接。
- 遮挡热力图。
- 暴露热力图。
- 机动空间热力图。
- 恢复安全热力图。
- 玩家完整飞船可达空间。
- 玩家受损飞船可达空间。
- Boss可达空间。
- 玩家可过、Boss不可过的窄口。
- 可破坏伏击路径。
- 敌人射线和入口方向。
- 每个位置可用解法数量。

玩家最终游戏中不会看见这些颜色和标签，它们只存在于策划Tool和调试视图。

### 13.6 候选 Seed 比较

Tool 提供“生成候选”操作，一次只生成少量候选，例如 4 或 8 个，不运行无上限搜索。

每个候选卡片显示：

```text
Seed
是否通过
平均可选解法数
最长连续暴露
最近恢复距离
有效Boss窄口
支配性路线
完整/受损玩家通过率
校验值
拒绝原因
```

策划可以：

- 双击候选进入场景预览。
- 将两个候选并排比较报告。
- 收藏候选。
- 锁定候选。
- 复制Seed给其他成员复现。
- 查看两个难度配置下同Seed的差异。

### 13.7 即时验证与错误分级

参数改变时先运行轻量规则验证，不立即重建整座城市：

- 红色：配置不可能成立，禁止生成或发布。
- 橙色：能够生成，但存在明显体验风险。
- 黄色：达到最低要求，建议实机确认。
- 绿色：通过当前自动验收。

示例错误：

```text
恢复慷慨度要求至少3个恢复机会，但当前地图尺寸最多容纳2个。
Boss窄口目标净空小于玩家受损包围盒。
同时把导航、暴露、敌人压力设为高档，超过局部预算上限。
目标机会数量无法满足每个主要问题至少两种解法。
```

所有警告都应说明“哪个策划参数导致问题、建议调整什么”，不能只输出底层断言名称。

### 13.8 隔离试玩

Tool 提供“打开隔离试玩”按钮：

1. 将当前候选烘焙到专用临时测试场景。
2. 选择完整玩家、受损玩家或Boss观察代理。
3. 只启动当前城市任务所需系统。
4. 记录玩家轨迹、机会进入、视线中断、碰撞和受击。
5. 退出 Play Mode 后自动回到Tool并展示行为报告。

隔离试玩不自动修改正式任务配置。策划必须点击“应用到任务”才能发布。

### 13.9 保存与发布

正式发布流程：

```text
选择或新建配置资产
→ 选择任务和星球
→ 调整语义参数
→ 生成少量候选Seed
→ 查看报告和热力图
→ 锁定候选Seed及校验值
→ 运行相关编辑器验证
→ 打开单个隔离场景试玩
→ 查看行为报告
→ 点击“应用到任务”
→ 保存配置资产
```

“应用到任务”必须保存：

- 配置资产 GUID。
- 配置版本。
- 锁定Seed或合格Seed池。
- 稳定校验值。
- 目标任务和星球绑定。
- 最后验证时间和结果摘要。

不要求把生成后的完整城市保存到正式场景；正式运行时仍可根据已发布配置和Seed稳定生成。

### 13.10 Tool 安全边界

- 不自动保存用户正在编辑的正式场景。
- 不静默修改Prefab和建筑目录。
- 不允许无上限批量生成。
- 不在参数滑动过程中持续实例化整座城市；松开滑杆或点击生成后才重建。
- 生成过程中允许取消，并保证预览根节点可完整回收。
- 所有策划配置操作支持Undo/Redo。
- 配置迁移前创建可恢复副本。
- 发布前必须通过最低物理可行性和战术覆盖验证。
- 只运行相关PCG编辑器验证和单个隔离战斗场景，不运行全量测试。

## 15. 推荐实施阶段

### P0：建立人工基准

使用现有素材手工或半手工搭建一张小型开放Boss城市，只包含：

- 一个最终目标。
- 一条暴露捷径。
- 一条连续遮挡链。
- 一个风筝环。
- 两组战术窄口。
- 一个恢复口袋。
- 一个破坏伏击点。

证明这些机会在现有飞船物理和Boss AI下确实产生不同打法。

### P1：战术字段与机会数据

- 建立物理能力包络。
- 从实际几何计算遮挡、暴露、机动、恢复和Boss阻挡分数。
- 建立机会节点、连接和查询接口。
- 保留现有网格和建筑实例化流程。

### P2：任务和AI接入

- 普通敌人入口和角色使用压力数据。
- Boss行为读取窄口、绕行和破坏机会。
- 任务目标引用机会网络，不再只使用裸世界坐标。
- 保证区域用途由战斗结果表达。

### P3：策划难度接口

- 实现 `CombatCityPcgDesignerWindow` Unity策划Tool，策划不直接操作底层组件。
- 实现版本化配置资产、Undo/Redo、候选Seed、锁定和发布流程。
- 增加语义参数和可复制难度模板。
- 增加局部压力预算。
- 增加六档星球曲线。
- 增加SceneView热力图、Seed报告和隔离试玩入口。

### P4：PCG拓扑生成与自动拒绝

- 从人工基准提炼多种非线性拓扑语法。
- 生成战术骨架后再适配道路网格。
- 运行完整/受损玩家和Boss代理仿真。
- 拒绝缺少解法、存在支配性路线或行为指纹不成立的Seed。

## 16. 第一版验收标准

第一版不要求生成大量城市变化，只要求一个配置能够稳定证明方案成立：

1. 玩家只看到“击败Boss”，不显示区域名称。
2. 玩家在开阔空间长期正面对打明显吃亏，但不是立即死亡。
3. 玩家进入楼群后能够真实切断视线并获得新的攻击角度。
4. 玩家穿过战术连廊后，Boss正常绕行或突破，不会静止卡死。
5. 玩家利用风筝环能够制造距离优势，但不能无限安全逃跑。
6. 受损玩家能够主动找到并使用自然恢复空间。
7. 切割建筑能够形成一次真实、可读、可重复理解的Boss伤害机会。
8. 至少两种不同打法可以完成任务。
9. 不存在明显优于全部其他策略的固定位置或固定路线。
10. 策划只通过Unity策划Tool修改语义配置，就能稳定改变机会数量、压力、可读性和操作要求，不需要修改代码、场景组件或裸配置资产。

## 17. 最终设计准则

```text
网格负责让城市稳定成立。
战术字段负责描述空间真实能力。
机会网络负责提供非线性选择。
敌人和Boss负责提出战斗问题。
任务只规定最终目的。
反馈负责让玩家理解空间用途。
难度配置负责控制机会与压力的比例。
验证器负责拒绝只有理论标签、没有实际体验的地图。
```

城市不需要看起来像真实商业区或工业区；它需要让玩家在战斗中不断产生：

> “我现在应该利用那片楼群断开视线，或者冒险走大道抢攻击角度；如果Boss追过来，我还能从连廊下面穿过去。”

当玩家能在没有区域文字提示的情况下做出这种判断，战斗驱动的城市 PCG 才算真正成立。
