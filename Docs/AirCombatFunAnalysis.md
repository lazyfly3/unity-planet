# 模块化空战体验逐项分析文档

## 1. 文档目的

本文件用于逐项分析当前 `ModularAssemblyLab` 空战为什么“不爽、不好玩”，并记录后续优化结论。

分析时不要直接从“增加特效”“提高伤害”开始，而要依次确认：

1. 玩家输入是否被正确理解。
2. 载具是否给出连续、可预测的运动响应。
3. 摄像机是否提供稳定、清晰的战斗视野。
4. 武器是否具备瞄准、前摇、爆发、命中和恢复节奏。
5. 命中是否产生清晰且有价值的模块损伤。
6. 敌人是否能够制造压力并形成攻防循环。
7. 拼装差异是否真正转化为战斗差异。

# 第一部分：驾驶手感

## 4. 输入语义分析

### 目标

玩家按下相同按键时，必须始终得到相同语义的运动结果。

| 输入 | 预期语义 |
|---|---|
| `W/S` | 沿摄像机水平前后移动 |
| `A/D` | 沿摄像机水平左右移动 |
| `Space/Ctrl` | 沿世界坐标上升和下降 |
| 鼠标 | 改变载具目标朝向 |
| `Q/E` | 主动翻滚 |
| `X` | 制动并稳定 |

### 当前重点问题

- WASD是否在任何载具姿态下都保持相同语义？
- Space和Ctrl是否会附带俯仰、偏航或翻滚？
- 鼠标转向是否与平移输入争夺控制？
- 地面模式和飞行模式是否存在输入冲突？
- 是否仍有旧控制器读取同一组按键？

### 复现测试

1. 使用核心单体进入试飞。
2. 将载具旋转到不同俯仰和滚转角度。
3. 分别单独按下每个移动按键。
4. 记录世界空间速度变化和角速度变化。
5. 检查非预期旋转是否出现。

### 验收标准

- WASD只产生预期平移，不直接生成姿态目标。
- Space和Ctrl只产生世界上下请求。
- 没有玩家旋转输入时，不应产生持续角加速度。
- 任意时刻只有一个移动协调器读取输入并施力。

## 5. 虚拟24向推力分配分析

### 当前设计

- 实体推进器分解到24个虚拟通道。
- 多轴请求使用共同限幅系数。
- 最弱方向决定组合移动的最大输出。
- 任一必要方向缺失时，整组平移可能停止。
- 标准模式不提供隐藏平移能力。

### 可能导致不好玩的原因

- 多按一个方向后，原本有效的移动突然归零。
- 推进器能力接近临界值时，输出发生明显跳变。
- 玩家无法从画面理解当前瓶颈方向。
- 轻微战损可能让完整控制矩阵突然降秩。
- 平移、旋转和稳定共享推进器后，玩家请求被大量削弱。

### 必须回答的问题

- 严格的“缺一轴整组归零”是否适合默认辅助驾驶？
- 是否应该只对玩家主动组合方向保持比例？
- 稳定器是否可以逐轴工作，而不是阻断整组请求？
- 组合输入的限幅变化是否经过平滑处理？
- UI是否能显示当前瓶颈和缺失方向？

### 对比实验

| 测试 | 方案A | 方案B | 玩家主观结果 |
|---|---|---|---|
| 前进 | 严格24向 | 平滑投影 |  |
| 前进+上升 | 最弱轴限幅 | 分组限幅 |  |
| 前进+横移 | 缺轴归零 | 保留主轴 |  |
| 单侧推进器损毁 | 立即重算 | 平滑降级 |  |
| 制动 | 与平移共享 | 独立制动预算 |  |

### 验收标准

- 单轴输入必须连续、稳定。
- 组合输入不能因为微小能力变化突然归零。
- 载具能力不足时应降低加速度，而不是随机改变方向。
- 战损后性能应逐步降低，而不是瞬间完全失控。
- 尾焰油门必须与最终分配结果一致。

## 7. 姿态稳定分析

### 设计目标

稳定系统应该修正轻微不平衡，但不能完全掩盖模块布局差异。

### 需要检查

- 无输入时角速度是否能够自然衰减？
- 平移输入是否产生非预期翻滚？
- 稳定器是否与鼠标目标朝向冲突？
- 稳定器是否在推进能力不足时持续满功率振荡？
- 单侧推进器损毁后是否立即产生无法停止的旋转？
- 核心辅助是否有明确上限？

### 好玩的降级方式

- 轻伤：轻微漂移，仍可稳定瞄准。
- 中伤：转向变慢，制动距离增加。
- 重伤：某些方向缺失，需要改变战术。
- 致命伤：无法维持飞行或无法继续战斗。

### 不应采用的方式

- 随机翻滚。
- 输入反转。
- 无上限镜头摇晃。
- 稳定器持续振荡。
- 轻微损坏后完全失去控制。

- 载具俯仰和翻滚不会直接带动镜头。
- 镜头长度使用插值。
- 横向和纵向偏移分别插值。
- 俯仰和偏航分别控制。

- 上升时载具是否移动到准星中央？

- 瞄准时是否仍使用普通驾驶构图？
- 镜头碰撞是否导致距离快速抖动？

- 载具主体位于画面下方约25%至40%区域。
- 载具不能遮挡准星周围主要射击区域。
- 上升和下降不改变载具在屏幕中的基本构图。

## 11. 弹道与伤害同步分析

### 核心原则

伤害必须由弹道的实际命中触发，而不是特效和伤害分别计算。

### 检查项目

- 实体弹丸是否使用连续碰撞或扫掠检测？
- Hitscan曳光是否保存开火瞬间的起点和终点？
- 已发射弹丸是否仍然读取鼠标或摄像机？
- 导弹是否只跟随已锁定目标？
- 目标丢失后导弹是否沿当前速度直飞？
- 弹体视觉前向是否与实际速度一致？
- 命中特效是否在伤害结算位置产生？
- 爆炸伤害是否具有距离衰减和遮挡检测？

### 验收标准

- 看见命中才产生伤害。
- 没有命中就不能扣血。
- 弹道视觉不能跟随发射后的鼠标移动。
- 多炮口曳光必须与各自真实伤害路径一致。
- 命中特效方向与碰撞表面法线一致。

## 12. 特效与声音分析

### 爽感链路

一次有效攻击应形成以下连续反馈：

`输入 → 武器响应 → 枪口反馈 → 弹道 → 命中 → 模块反应 → 功能变化`

### 视觉检查

- 枪口特效是否从真实枪口产生？
- 尾焰是否只从喷口向排气方向产生？
- 尾焰长度是否反映真实油门？
- 粒子是否使用正确材质？
- 是否仍存在白色方块或紫色错误材质？
- 爆炸是否过大并遮挡战场？
- 世界空间尾迹是否会随载具旋转？
- 高速效果是否清晰但不过度遮挡？

### 声音检查

- 是否存在推进器启动、持续和停止声音？
- 是否存在武器预热、发射、循环和结束声音？
- 是否区分装甲、结构、护盾和核心命中？
- 是否有模块断裂和功能失效声音？
- 声音音量和音调是否反映实际输出？

### 验收标准

- 视觉、声音、伤害和物理变化在同一事件链中触发。
- 特效不能遮挡准星和目标。
- 不同武器具有不同的视听识别度。
- 推进特效必须准确表示实际动力状态。

## 13. 模块伤害分析

### 目标

玩家攻击的不是一条总血量，而是敌人的具体功能。

### 模块损伤阶段

| 生命比例 | 推荐表现 |
|---:|---|
| 50%以上 | 功能完整 |
| 25%至50% | 输出降低、响应变慢、出现烟火 |
| 0%至25% | 严重故障、功能明显衰减 |
| 0% | 模块摧毁并退出系统 |

### 当前需要确认

- 命中是否只伤害实际碰撞到的模块？
- 模块耐久是否与类别匹配？
- 是否存在缩小模型代替真正破坏的问题？
- 模块归零后是否立即退出功能计算？
- 损坏是否会影响质量、重心和惯量？
- 损坏是否会影响推进、升力、武器和能源？

### 验收标准

- 损坏具体模块必须产生对应功能变化。
- 装甲损坏和推进器损坏必须具有不同意义。
- 不使用简单缩放模型表示模块摧毁。
- 功能变化必须与视觉变化同时发生。

## 14. 结构连接与断裂分析

### 结构模型

载具结构使用无向接触图：

`G = (V, E)`

| 符号 | 含义 |
|---|---|
| `V` | 核心、结构、武器、推进器、机翼等模块 |
| `E` | 模块之间有效的六面接触关系 |

模块摧毁后：

`G' = G - v`

然后从核心重新遍历连接图。

### 正确断裂流程

1. 命中模块耐久归零。
2. 从接触图删除该节点和关联边。
3. 从核心执行连接遍历。
4. 标记所有不再与核心连通的分量。
5. 立即关闭断连模块功能。
6. 播放断裂、火花和消失效果。
7. 从载具质量和控制系统中移除这些模块。

### 当前重点问题

- 双路径连接是否会被错误判定断开？
- 唯一桥接块摧毁后，后方模块是否整体失效？
- 断连模块是否仍贡献推力或武器？
- 是否存在两套伤害接收器重复扣血？
- 战斗胜负是否在结构更新完成前判断？
- 断裂是否导致战斗过早结束？

### 验收标准

- 双路径结构摧毁一条路径后仍保持连接。
- 唯一连接被摧毁后，后方功能模块整体失效。
- 断连模块不能继续射击、推进或提供能源。
- 每次结构变化只触发一次统一重算。

## 15. 战斗能力判定分析

### 当前可能的问题

- 核心连通CPU比例过低时立即结束。
- 全部武器失效后立即结束。
- 短时间升力不足被误判为无法战斗。
- AI尚未进入交战就被判定失能。
- 单个关键模块断裂导致整场突然结束。

### 推荐状态

| 状态 | 含义 |
|---|---|
| `Operational` | 功能完整 |
| `Degraded` | 性能下降但可正常战斗 |
| `Critical` | 严重受损但仍可挣扎 |
| `Ineffective` | 无法继续形成有效战斗 |

### 判定原则

- 瞬间状态不能直接结束战斗。
- 飞行能力不足应设置持续时间。
- 武器全部失效可以判负，但应保留明确反馈。
- 战斗结束前应完成最后一次断裂和爆炸展示。
- 不应因为轻微漂移或短暂失速立即判负。

# 第六部分：拼装价值

## 18. 拼装差异分析

### 核心问题

玩家花费时间拼装后，进入战斗是否能明显感受到设计差异？

### 对比蓝图

至少准备以下测试载具：

| 蓝图 | 特征 |
|---|---|
| 轻型高速 | 少装甲、多推进器 |
| 重型装甲 | 高质量、高耐久 |
| 紧凑机动 | 质量集中在中心 |
| 长轴稳定 | 质量分布在前后 |
| 固定翼 | 大面积机翼、高速升力 |
| VTOL | 垂直推进器和姿态推进器 |
| 武器平台 | 多武器、低机动 |
| 高冗余 | 多连接路径、多组推进器 |

### 必须出现的差异

- 加速度不同。
- 最高速度不同。
- 制动距离不同。
- 转向速度不同。
- 滚转和俯仰惯量不同。
- 武器射界不同。
- 战损后的冗余不同。
- 能源和热量持续能力不同。

### 验收标准

- 不看模块统计也能通过驾驶感分辨载具类型。
- 改变推进器位置能够改变转向能力。
- 增加装甲能够提高生存能力，但降低机动性。
- 增加结构冗余能够降低被一刀切断的风险。
- 每一种有效设计都具有明确优势和代价。

# 第八部分：建议处理顺序

## 21. P0：先解决可玩性

1. 确认只有一个移动控制器施力。
2. 修复组合输入突然归零。
3. 固定摄像机构图，避免载具遮挡准星。
4. 统一准星、炮口、弹道和伤害点。
5. 修复模块摧毁和结构断连流程。
6. 修复AI不接敌或不开火。

## 22. P1：建立战斗节奏

1. 为九种武器建立独立状态机。
2. 增加武器前摇、爆发和恢复差异。
3. 完善命中、受损和断裂反馈。
4. 增加屏幕外敌人和威胁提示。
5. 调整战斗距离、时长和结束条件。

## 23. P2：增加深度

1. 强化机翼、推进器和质量布局差异。
2. 完善能源、热量和弹药管理。
3. 增加AI受损后的战术变化。
4. 增加不同敌机蓝图和战斗风格。
5. 建立系统化数值平衡和性能测试。

# 24. 最终判断标准

优化后的空战需要同时满足：

- 玩家知道自己输入了什么。
- 玩家能预测载具将如何响应。
- 玩家能看清敌人和准星。
- 玩家知道武器为什么能开火或不能开火。
- 玩家看到弹道命中后才发生伤害。
- 玩家能看懂敌人失去了哪个模块和功能。
- 玩家能感受到自己的拼装设计带来的优势和代价。
- 即使战斗失败，玩家也能理解失败原因并回到改装界面改进设计。

最终目标不是让所有载具性能相同，而是：

> 大部分合理设计都能正常操作，不同设计拥有明显差异，错误设计表现为可理解的性能不足，而不是无法解释的失控。
