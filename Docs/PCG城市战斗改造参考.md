# PCG 城市战斗改造参考

> 状态：第一版设计与运行基线已于 2026-08-09 接入正式城市任务和城市试飞流程。  
> 本文同时保留后续调参与人工体验验收标准；“验收重点”中的主观手感项仍需玩家实机判断。

## 0. 第一版实现落点

当前代码已经完成以下闭环：

- `RecoveryPocket` 的 PCG 数据名称暂时保留以兼容已有 Seed、报告和测试，但 EDPCG 运行语义已经改为 `MagneticCourtyard`；只有出生空域继续获得压力减免，原庭院不再得到隐藏安全窗口。
- 正式有限星球城市任务与模块化城市试飞都挂载同一个 `UrbanEnvironmentalFieldDirector`，不会出现只在实验场生效的分叉实现。
- 每座第一版城市只选择一条确定性的长街风场，并从两个原恢复庭院生成三面磁场；同一城市最多只有一个环境场处于 `Warning / Active`，避免风和磁场同时乱开。
- 自然风使用固定街道方向、三点建筑遮挡采样、边界渐变、拉伸软粒子和地面流线；`D:/untiy素材/风/Realistic ARPG Wind Magic Spells 1.0.unitypackage` 属于完整魔法技能 ShaderGraph 包，与自然街谷狂风的方向性和当前渲染链不匹配，因此没有整包导入。
- 磁场使用三面实体连续碰撞代理和状态灯轨：暗蓝关闭、黄色充能、高亮红色开启；吸力保持水平，顶部始终是主要逃生方向。
- 环境力通过现有 `VehicleExternalForces / RobocraftMotionCoordinator` 进入力账本，不修改 Rigidbody 质量、重力、基础阻力、推进参数或原难度数值。
- 同一有限外力使重型改装获得更低加速度；风力额外读取暴露面积、阻力面积、翼面积和吸力反方向的推进权限，磁力读取质量与方向推进权限但不错误复用“机翼抗风”。
- 街机模式降低玩家环境扰动并缩短贴墙保持效果，但不免疫；标准模式保留完整扰动。敌人数值、波次、场状态和视觉提示不随模式变化。
- 风场只在敌机真实撞击静态建筑且超过速度阈值时结算环境碰撞伤害；小型敌机可被撞毁，玩家只对实际接触侧模块结算有上限的单次伤害。
- 三面磁场为不同飞行器选择稳定墙面和横向接触槽；释放时取消朝墙速度、施加向庭院内的分离偏置，并以 `Physics.ComputePenetration` 和最后安全姿态处理异常穿透。
- 普通敌机保留原导航、攻击令牌和难度曲线；只有确定性的一部分截击机/突击机会跟随玩家进入风街或庭院，炮艇保持远程职责。磁场压住敌机时只暂停其精确射击许可，推进和导航继续抵抗；释放后进入短暂姿态恢复并重新接敌。
- Boss 使用同一有限环境力和真实质量，因此会受到风和磁场影响但通常更难移动；第一版没有让普通子弹借环境场破坏建筑，也没有给环境场增加新的 HUD 信息或专用操作键。
- 城市模板原有的边界外无碰撞低模天际线继续作为视觉城市壳层使用，环境场不会向远景注册碰撞、导航或战斗节点。

## 1. 改造结论

城市中的特殊空间必须直接改变战斗关系，不能只依赖隐藏的数值规则让某个区域“安全”。

本轮首先确定以下方向：

1. 移除“修复区 / 恢复庭院”作为固定城市战术区域。
2. 移除玩家进入某个区域后，代码直接降低敌人压力或限制敌人攻击的硬约束。
3. 飞船修复不再是该区域的身份；是否能修复应由真实脱战条件、装备、技能或其他独立系统决定。
4. 原“三面建筑、顶部开放”的庭院空间可改造成动态环境战术装置。
5. 第一批考虑两类装置：风场与磁场。
6. 风场、磁场不一定永久开启，可以关闭、待机、充能、脉冲启动、冷却或被破坏。
7. 装置必须同时影响玩家与敌机，但不要求严格对称；玩家应保留更多操作空间和更可靠的生存下限。
8. 可玩城市外围增加独立的低成本视觉城市壳层，隐藏地面与楼群边界，让战斗空间在视觉上属于一座继续向远方延伸的城市。
9. 风场只采用自然狂风，不要求机械风扇或喷口；狂风沿街道从一端吹向另一端，并被合并街区中的实体楼体遮挡。
10. 第一版磁场只使用原恢复庭院的“三面建筑、顶部开放”几何，改造成三面磁力捕获庭院。
11. 风与磁场都属于对力的模拟和物理关系的表现；实现时不替换或重做当前飞船物理模型，只增加有边界的环境力影响层。
12. 环境陷阱必须能被玩家真正用于击杀小兵或创造输出窗口，同时保持现有难度曲线，不通过增加敌人数值、数量或伤害来补偿玩家获得的战术收益。
13. 环境场必须在玩家当前键鼠操控和真实改装数值下可利用；不增加专用“抗风键”，整船质量、质心、惯量、推进权限与机翼气动数据都要实际影响抗风结果。

核心目标不是制造另一个安全区，而是让玩家利用环境改变敌人的位置、速度、队形和攻击条件。

```text
在道路上被追击
→ 观察自然天气或磁场颜色状态
→ 引导敌机进入作用范围
→ 环境场延迟生效
→ 敌机被吹向建筑或吸向磁力墙
→ 玩家承担可控风险并获得反击窗口
```

## 2. 为什么移除修复区

三面有建筑、顶部开放的庭院，在空战中并不天然安全：

- 高空敌机可以从顶部俯射。
- 自爆机可以从上方进入。
- Boss 可以悬停在出口上方或进行俯冲。
- 玩家单看建筑外形，无法理解这里为什么会让敌人降低压力。
- 如果安全性仅来自代码标签，玩家容易认为敌机 AI 变笨，而不是自己做出了战术选择。

因此不再保留以下规则：

```text
玩家进入修复庭院
→ 敌人压力上限自动降低
→ 玩家获得不可见的恢复窗口
```

推荐替换为：

```text
玩家进入特殊庭院
→ 观察并触发真实环境装置
→ 玩家和敌人都受到明确物理作用
→ 战斗队形和射击条件发生可见变化
```

原有庭院几何不一定删除，可以改造为风场井、磁力捕获庭院或其他动态环境战斗节点。

## 3. 动态环境场的共同规则

### 3.1 状态机

自然风和磁场都需要清楚的状态节奏，但产生原因不同：自然风通过天气与街道环境预兆进入强风阶段，磁场通过装置充能进入开启阶段。

```text
Disabled（损坏或未供电）
    ↓
Idle（可用但未开启）
    ↓ 触发
Charging（充能警告）
    ↓
Active（持续或脉冲生效）
    ↓
Cooldown（冷却）
    └────────→ Idle
```

不是每个装置都必须包含全部状态，但不能只存在“毫无提示的关闭”和“瞬间满强度开启”两种状态。

### 3.2 可选启动方式

- 周期脉冲：按稳定节奏开启和关闭，玩家可以学习时机。
- 接近触发：玩家或敌机进入感应区后开始充能。
- 延迟陷阱：玩家通过后开始充能，让后方追击敌机进入作用范围。
- 战斗触发：附近发生爆炸、Boss 攻击或装置受到伤害后启动。
- 可控装置：玩家射击开关、摧毁锁定器或短暂占领后启动。
- Boss 控制：Boss 主动开启、反转或破坏装置。
- Seed 变体：同类庭院在不同城市中拥有不同启动规律。

“玩家经过以后装置突然打开”可以保留，但应满足：

1. 玩家经过感应器时能看到或听到装置被唤醒。
2. 从唤醒到满强度之间保留短暂反应时间。
3. 启动方向和主要危险可以从环境动画中判断。
4. 首次触发不能在玩家完全没有操作机会时直接造成致命碰撞。

### 3.3 状态提示

提示优先来自世界本身，不依赖 HUD 箭头或信息栏文字。

| 状态 | 风场提示 | 磁场提示 |
|---|---|---|
| Idle | 悬挂物轻摆、街口远尘尚未进入，当前没有足以影响飞行的强风 | 磁力板保持暗蓝定位光，碎屑落地，没有吸力 |
| Charging | 上游尘雾聚集、云层快速掠过、纸屑和轻物开始朝同一方向滑动 | 黄色灯带逐段推进，碎屑轻微悬浮，低频嗡鸣增强 |
| Active | 强烈气流、布条和粒子统一指向；自然风形成贯穿街道的可见流线 | 三面磁力板切换为高亮红色，碎屑高速吸向墙面，电弧和嗡鸣达到峰值 |
| Cooldown | 风速下降、尘雾带离开街道，悬挂物逐渐停止剧烈摆动 | 红色逐段熄灭并回到暗蓝，碎屑掉落，嗡鸣降低 |
| Disabled | 自然风不使用损坏状态，只存在当前天气周期是否会经过该街道 | 磁力板无光且伴随损坏火花或冒烟，与正常关闭的暗蓝状态区分 |

磁场以颜色作为玩家判断开关状态的第一判据：暗蓝表示关闭但可用，黄色表示即将开启，高亮红色表示吸力正在生效。颜色之外仍保留碎屑运动、线圈动画和声音作为冗余，避免玩家在激烈战斗、远距离或色觉差异下失去判断。

环境装置还必须有统一且明确的城市标识，不能等玩家被吸住或吹飞以后才知道它是什么：

- 自然风不使用机器标识。玩家通过街道朝向、上游尘墙、云层移动、飘带、广告布、线缆、纸屑和地面积尘判断这条街是否会起风以及风向。
- 磁场使用固定形状的线圈、马蹄形磁体符号、墙面磁力警示牌、金属碎屑与高压隔离纹样。
- 同一种装置在不同 Seed 中可以改变尺寸和位置，但标识形状、启动动画和核心声音必须一致。
- 玩家从装置作用范围外，就应能辨认装置类型、当前状态以及主要危险方向。

### 3.4 物理模型与难度曲线不变量

风场和磁场都应被理解为环境向飞行器施加的力，而不是进入 Trigger 后直接播放位移或扣血：

- 保留当前玩家飞船和敌机的基础移动、推进、转向、碰撞与模块系统，不重新设计整套飞行物理。
- 不为风场或磁场全局修改 Rigidbody 质量、阻力、重力、最大速度或现有推进参数。
- 新增独立的环境力影响层，只向现有运动系统提供经过限制的方向、强度、扰动和控制修正。
- 环境力层读取当前装配计算出来的总质量、质心、惯量、气动面积与各方向推进权限，不另建一套脱离改装系统的固定“玩家抗性”。
- 当前项目存在两条需要兼容的飞行环境链路：模块化玩家飞船由 `RobocraftMotionCoordinator` 从 `IPlanetEnvironmentProvider / PlanetEnvironmentSample` 读取重力、平均风、阵风和大气数据；另一条地表飞行链路由 `PlanetSurfaceFlightEnvironment` 把 `PlanetaryFlightContext` 交给 IFCS。城市战斗实际使用哪条链路，就把自然风接入对应的统一环境样本，不能另写一次并覆盖原有重力或气动力。
- 磁力等新增场力也必须进入当前拥有 Rigidbody 的运动协调器和力账本，并让对应控制辅助知道正在抵抗外力。不能依赖一个在当前飞行模式下被忽略或每帧清零的独立值，让画面受力而飞控不知情。
- `RobocraftMotionCoordinator` 当前独占模块化飞船物理，并提供 `TryApplyExternalImpulseInCurrentPhysicsStep / QueueExternalImpulse` 进入现有力账本。磁力应使用该入口或在同一账本中增加连续场力通道，不能由另一个组件并行直接 `Rigidbody.AddForce`，否则容易重复施力、破坏遥测与执行器闭合结果。
- 环境力不得瞬移目标；位置变化应由当前运动结果逐步产生。
- 风场和磁场本身不直接造成伤害。小兵死亡或玩家模块受损应来自真实撞墙结果；磁场捕获只负责产生吸力和短暂控制窗口。
- 采用伪物理是允许的：重点是方向、遮挡、受力反馈和结果一致，而不是建立完整空气动力学或电磁学模拟。

增加环境陷阱不等于修改难度曲线：

- 不改变各难度原有的敌人生命、伤害、射速、精度、波次数量、出生节奏或难度倍率。
- 不因为玩家可以利用陷阱，就额外补怪或增强 Boss。
- 不根据难度等级随意放大风力、磁力或捕获时间；第一版环境规则跨难度保持一致。
- 会利用城市的玩家可以让局部战斗变容易，这是地图战术带来的奖励，不需要用数值补偿抹平。

## 4. 风场

### 4.1 战斗用途

风场不是单纯把玩家向上送，而是可以改变追击队形：

- 把高速追击敌机推向建筑。
- 把敌机压缩到同一条受力方向，方便范围技能反击。
- 把道路上的横向包围转换为可预测的纵向或侧向位移。
- 干扰导弹转向与稳定追踪，但不让普通实体子弹凭空消失。
- 把玩家快速送到另一高度层或另一条楼顶航线。
- 在 Boss 战中改变冲撞方向，或让 Boss 破坏风场设施。

### 4.2 风从哪边往哪边吹

每个风场实例必须拥有明确且稳定的主风向，不能在作用范围内随机改变受力方向。PCG 必须同时生成并记录以下空间关系：

```text
风源 Source
→ 主风向 Primary Direction
→ 有效风道 Influence Corridor
→ 撞击面或高度出口 Destination
```

自然风的方向必须通过整条街道的环境共同表达：

- 风从街道一个明确的上游尽头进入，沿道路轴线吹向另一个下游尽头。
- 上游尽头先出现移动的尘墙、低云、雾带或被卷起的轻质碎片，让玩家在强风到达前看见来源。
- 广告布、横幅、线缆、纸屑、地面积尘和气流特效统一朝下游方向运动。
- 无风阶段也应保留静态街道构图和少量悬挂物，使玩家知道这是一条可能形成街谷风的长通道。
- 预警阶段先让远处尘雾和近处轻物开始定向运动，再逐步施加完整风力。
- 同一次 Active 状态只使用一个主风向，不在街道中途或每一帧随机反转。

这里的“道路尽头”必须按完整街道拓扑判断，不能直接使用 PCG 为铺路、路口或街区切分产生的单段 `RoadStrip.start / end`：

- 同一轴线、同一街宽方向且首尾相接的道路段，必须先合并为一条最大连续直路；普通十字路口只是道路中间，不是风源，也不是终点。
- 最大连续直路接到城市道路边界时，该边界才是道路尽头；自然风从其中一个尽头的薄入口面生成，不能在整段道路中随机出生。
- 合并街区移除了一段道路或实体楼体横断街谷时，连续关系在缺口前终止，该迎风面可以成为这条局部风道的真实终点；不能借用飞行路线数据让风穿过被删除的道路。
- 没有道路缺口和实体遮挡时，风的视觉、受力与遮挡检测必须从上游尽头连续覆盖到下游尽头，不允许使用固定粒子寿命形成“只吹中间一截”的假长街。

第一版只要求一种最容易读懂的布局：自然狂风从长街一端吹向另一端。PCG 在中间生成合并街区和实体楼体，楼体既能形成背风空间，也能作为敌机被风拍中的撞击面。

不允许生成“看不到上游、看不到下游、没有环境预兆、整个空间各处受力不同”的抽象风盒。玩家应当能够在狂风到达前，用一句话说明“风会从那边的街口沿这条路吹向另一头”。

### 4.3 自然街谷狂风与合并街区

自然狂风不是覆盖全城的天气伤害，而是一段被高楼街谷约束的局部强风：

```text
上游街道尽头出现尘墙和风声
→ 狂风沿道路轴线向下游推进
→ 开放道路承受完整风力
→ 合并街区的实体楼体挡住风
→ 楼体背后形成明显的弱风区或背风区
→ 追击小兵暴露在道路上，被拍向下游或侧前方墙面
```

合并街区必须真正参与风场空间计算：

- 建筑实体是风力遮挡体，狂风不能无条件穿过楼房继续作用。
- 建筑迎风面承受风，背风面形成衰减区；玩家可以主动躲到楼体后稳定飞船、观察敌机并准备反打。
- 楼角允许出现有限的侧向扰动，但不能制造无法预测的随机涡流。
- 背风区必须足够容纳玩家飞船的正常机动，不只是贴墙的一条狭窄无风线。
- 从背风区离开重新进入主街时，风力逐步恢复，不能在边界一帧内从零跳到最大。
- 下游必须有至少一个经过 PCG 验证的实体撞击面，使追进主风道的小型敌机可能真实撞墙。

自然风的视觉表现可以使用风素材包中的 `WindBand`、雾状气流和碎屑，但需要改造成沿街道循环的环境效果，不能直接放大角色魔法 Prefab，也不能出现符文、法阵或法术爆炸语言。

### 4.4 敌机受到的影响

- 敌机 Rigidbody 接受真实、连续或脉冲式风力。
- 敌机仍可尝试用推进器抵抗，不应直接瞬移到墙上。
- 小型敌机受力明显，重型炮艇受力较弱。
- 敌机撞击真实建筑碰撞体时，根据撞击速度、质量和角度受到伤害。
- 撞击伤害应来自碰撞结果，而不是“进入风场范围就扣血”。
- 小型普通敌机的有效撞击强度超过其环境碰撞阈值时，可以直接撞毁；这是风场作为战斗陷阱的核心收益之一。
- 中型、重型敌机和 Boss 不要求一次撞毁，可以受到伤害、偏航、丢失射界或暴露模块。
- 被吹乱的敌机需要短暂恢复姿态和重新接敌。
- 已经失控的敌机可以被玩家继续射击，但控制失效时间应有上限。

风场成功时应形成清楚的因果链：

```text
风场启动
→ 敌机飞行姿态被推偏
→ 敌机真实撞上楼房
→ 墙面出现碰撞反馈
→ 小型敌机直接撞毁，或幸存敌机脱离墙面并尝试恢复控制
```

### 4.5 玩家受到的影响

玩家同样受到风力：

- 飞船会被明显推离原航线。
- 玩家可以用推进、侧移和姿态控制抵抗。
- 玩家撞墙时可以让局部模块受到一定碰撞伤害。
- 环境风场不能因为一次普通撞墙直接让完整飞船爆炸。
- 核心模块需要保留生存下限，除非玩家本来已经严重受损。
- 连续碰撞需要伤害冷却或递减，避免飞船贴墙后每个物理帧重复扣血。
- 玩家脱离风场后应较快恢复正常控制，避免长时间失控。

建议把玩家环境碰撞伤害控制为“产生后果但通常可以继续战斗”。具体数值以后按手感调整，不需要现在设为严格常量。

可参考的初始保护原则：

- 单次风场撞击优先伤害受撞一侧模块。
- 完整核心不能因一次标准风场脉冲直接归零。
- 同一面墙的重复碰撞在短时间内递减。
- 玩家受到的最大角速度和最大环境附加速度需要限制。
- 若玩家仍有推进能力，应始终保留挣脱可能。

### 4.6 改装质量、推进权限与机翼的伪物理抗风作用

抗风能力必须来自玩家当前这架改装飞船，而不是所有玩家使用同一个隐藏抗风值。当前模块化飞控的 `RobocraftTelemetry` 已包含总质量、质心、惯量、正负方向力/加速度、暴露面积、阻力面积、翼面积、气动转矩、平均风与阵风等结果；兼容的 SpacecraftEditor 装配也能提供总质量、方向推进权限和机翼/鸭翼/垂尾气动资料。风场应读取正在拥有 Rigidbody 的那套最终装配结果。

各项改装的作用建议如下：

- **整船质量**：相同风力作用下，较重飞船的平移加速度和速度偏移更小；较轻飞船更容易被吹离航线。模块化城市流程优先读取 `RobocraftTelemetry.totalMass` / Rigidbody 最终质量，旧装配链路可读取 `ShipAssembly.Metrics.totalMass`；两者都必须包含当前实际安装模块，不能只按船体型号判断。
- **质心与惯量**：模块安装位置已经会改变质心和惯量。风力作用点偏离质心越多，越容易产生滚转或偏航；惯量较大的飞船姿态变化较慢，但原有转向和恢复代价也继续存在。
- **推进权限**：玩家按下抵抗方向后，实际效果由当前前后、侧向、升降与姿态推进能力决定。推进器更多或布局更合理的飞船能更快修正，但不额外获得风场专用推力。
- **机翼、鸭翼与垂尾**：主要改善侧风稳定、机头保持和姿态恢复，降低狂风造成的侧向漂移、滚转扰动与转向迟滞。
- **模块尺寸与暴露面积**：使用当前物理重建后的最终质量、`exposedArea / dragArea / wingArea` 与真实外形。存在可缩放部件的旧装配链路再使用缩放后的质量和气动面积；不能假设所有模块都按同一个缩放公式处理。
- **模块受损**：受损或脱落的机翼降低稳定贡献；推进模块受损则通过现有推进权限自然降低抵抗能力。左右状态不一致时，可以产生有上限的偏航或滚转倾向。

机翼贡献不通过显示名称或模型名称硬编码。当前模块化飞控优先读取 `AeroSurfaces` 与遥测中的 `wingArea`、气动转矩和控制面权限；SpacecraftEditor 链路中的 `SweptWing`、`DeltaWing`、`Canard`、`VerticalFin` 已有 `ShipAerodynamicProfile`，再以 `Role`、`ReferenceArea`、`SideStabilityCoefficient` 和最终缩放数据识别。这样资源改名或显示名称变化不会让抗风失效。

风场不重新设计空气动力学，而是在现有结果上增加可读、可调的抗风差异：

- 机翼不让飞船完全免疫风，也不把完整风力直接清零；玩家仍能看到位置被推移并感到逆风操作压力。
- 抗风计算通过环境力适配层影响当前操控结果，不修改飞船原有质量、推进、阻力和基础转向参数。
- 机翼只降低风对“操控”的影响，不直接减少撞墙后的模块碰撞伤害；避免把机翼同时做成隐形减伤装甲。
- 重型飞船不能完全免疫狂风，轻型飞船也不能被一次标准风脉冲直接判死；质量影响使用有上下限的连续曲线。
- 不用环境系统重新计算玩家原有的加速、制动和转向代价。重型改装抗风更稳，但其现有机动代价仍然存在，因此不会成为无条件最优解。

建议采用以下伪物理关系作为设计语义，而不是要求严格照搬公式：

```text
原始风载荷 = 当地风速、受风方向、机体/机翼有效面积与遮挡结果
质量易感度 = 有上下限的函数（参考质量 / 当前总质量）
机翼稳定 = 健康气动面积、气动角色、安装方向与侧向稳定系数的有上限结果
姿态扰动 = 原始风力矩 / 当前惯量 ×（1 - 机翼稳定）
平移扰动 = 原始风载荷 × 质量易感度 ×（1 - 有上限的机翼控制修正）
玩家抵抗结果 = 当前各方向推进权限与运动协调器 / IFCS 对上述扰动的实际修正
最终运动结果 = 当前飞行模型结果 + 受限的环境扰动
```

这样同一股风对轻型高机动、重型高惯量、宽翼稳定和受损不对称飞船会产生不同但可解释的结果，同时不会为一个城市陷阱重写现有物理模型。

### 4.7 风场变体

- 长街顺风：第一版采用，从街道一端持续吹向另一端。
- 路口横风：未来可选，只在开放十字路口短时穿过，不进入第一版。
- 楼间上升气流：未来可选，由高楼热压形成，不使用机械喷口。
- 风暴脉冲：未来可选，尘墙经过时产生一次强风，之后进入较长平静期。

## 5. 磁场

### 5.1 战斗用途

第一版磁场的主要功能是把飞行器吸向原恢复庭院的三面磁力墙，短暂改变位置与控制权：

- 把敌机吸向三面庭院中最近或主要作用的磁力墙。
- 把分散敌机聚集起来，制造范围输出窗口。
- 暂时限制敌机移动，让玩家重新瞄准或选择出口。
- 让玩家也被拉向磁力墙，从而形成高收益、高风险区域。
- 第一版只影响玩家、敌机和 Boss 等飞行器，不扩展到子弹与导弹，避免改变现有武器平衡和难度曲线。

### 5.2 磁场的方向与标识

磁场不能只是一个看不见的球形 Trigger。第一版只存在三面捕获型：三面建筑各有大型磁力板，进入庭院的目标被分配到最近或吸力最强的磁力面。

三面磁力板不能简单叠加出一个方向不明的合力。激活时应由最近磁力面、目标进入角度和当前速度确定主要吸附面，并在一次捕获期间保持稳定，避免敌机在三面墙之间高速抖动。

主要吸附面一旦确定，应使用距离滞回和最短保持时间；只有原吸附面损坏、目标真正越过墙面分界或出现不可达情况时才重新选择。位于墙角的目标不能因为三面距离每帧交替而被拉进建筑接缝。

磁场标识至少包含：

- 建筑立面上尺寸足够大的线圈或磁力板，而不是只贴一张小图标。
- 统一的马蹄形磁体或磁力捕获符号。
- 待机时垂落的金属链、碎屑和维护吊臂。
- 充能时逐段点亮的墙面线圈、开始抖动并升起的金属碎屑、增强的低频嗡鸣。
- 开启时朝具体吸附面飞去的碎屑、电弧和拉伸方向一致的局部特效。

三面磁场的颜色规则固定为：

| 磁场状态 | 三面磁力板颜色 | 玩家判断 |
|---|---|---|
| Disabled | 完全无光，并有损坏火花或冒烟 | 装置损坏，本轮不会开启 |
| Idle / Off | 暗蓝色轮廓光 | 磁场可用，但当前没有吸力 |
| Charging | 黄色灯带从入口侧向三面墙逐段推进 | 磁场即将开启，应从顶部脱离 |
| Active / On | 三面墙统一高亮红色 | 磁力正在生效，进入会被吸向墙面 |
| Cooldown | 红色逐段熄灭并恢复暗蓝 | 吸力正在消失，稍后可再次触发 |

颜色是第一判断信号，必须在玩家高速飞行时仍有足够面积和亮度。金属碎屑、低频声音和电弧只用于强化颜色含义，不能让三面墙颜色互相矛盾。

### 5.3 敌机受到的影响

- 磁场产生指向选定磁力墙的吸力。
- 吸力随距离增强或减弱的曲线必须稳定，不能在边界突然跳变。
- 小型敌机可能被吸附并短暂无法移动。
- “无法移动”应表现为推进器仍在抵抗，但合力不足以脱离，而不是 AI 被无理由关闭。
- 捕获时间应有限，之后敌机恢复控制或装置进入冷却。
- 重型敌机和 Boss 应具备更高抗性，但不能完全无视磁场。
- Boss 可以破坏线圈或用自身质量造成装置过载；第一版不反转吸力方向。

### 5.4 玩家受到的影响

玩家也会被吸向磁场：

- 飞船位置和朝向会被拉偏。
- 玩家可以持续输入推进器来减缓或挣脱吸力。
- 玩家不建议受到与普通敌机完全相同的硬性停机。
- 玩家被吸到墙体或核心结构时，可以受到局部模块碰撞伤害。
- 完整飞船不能因为一次正常磁场捕获立即爆炸。
- 玩家应能通过提前加速、现有方向推进或离开核心范围挣脱；第一版不能假设玩家拥有某个特定技能。

这种非严格对称是允许的：敌机可以获得更明显的短暂捕获效果，玩家则保留有限操控，但玩家仍必须真实承受吸力和错误判断的代价。

### 5.5 玩家改装对磁力吸附的影响

磁场不能给所有玩家飞船施加完全相同的位移曲线。它读取与当前装配一致的物理和控制数据，但不凭空增加“金属含量”属性：

- **整船质量**：同一墙面磁力作为受限外力时，较重飞船获得的吸附加速度更小，较轻飞船更快偏离航线。质量来自当前装配总质量，不按船体外观或难度等级写死。
- **推重比与方向推进权限**：能否抵抗磁力取决于吸附方向反向的可用推进力。某个方向缺少推进器、推进器布局不合理或模块受损时，该方向更难挣脱；系统不额外赠送“磁场逃生推力”。
- **质心与惯量**：磁力作用方向偏离质心时会产生有上限的姿态扰动，惯量和模块布局影响转动速度。为保证可操作性，平移吸力是主要结果，附加转矩不得大到让鼠标与 `Q / E` 完全失效。
- **飞船尺寸与突出模块**：翼展、武器、侧舱和其他突出部件不直接提供抗磁加成，但会改变最先接触墙面的真实位置、所需安全间距和卡住风险。
- **机翼气动数据**：机翼不会无理由降低磁力；它只通过自身质量、安装位置、惯量和外形参与结果。避免一套“机翼抗风”系数同时被错误用于磁场。
- **撞击代价**：重型飞船较难被加速，但一旦以较高速度撞墙，碰撞动量也更大；现有玩家单次环境碰撞保护仍防止完整飞船一次爆炸。质量因此是取舍，不是纯抗性收益。

在没有独立模块材质或磁化率数据前，不根据涂装、显示名称或“看起来像金属”推断吸力。第一版只使用项目已经可靠存在的总质量、质心、惯量、推进权限、模块状态和碰撞外形。

建议语义如下：

```text
墙面磁力 = 当前状态强度 × 距离衰减 × 目标类别倍率
吸附加速度 = 有上限的墙面磁力 / 当前总质量
可抵抗能力 = 吸附反方向的当前推进权限 / 当前总质量
姿态扰动 = 有上限的磁力矩 / 当前惯量
实际结果 = 磁场受力 + 玩家持续输入 + 当前运动协调器 / IFCS 与现有碰撞解算
```

### 5.6 捕获时间与玩家控制权

“控制时间”不是禁用玩家输入的眩晕计时器，而是磁场强度足以压过当前改装反向推进权限的持续区间：

- `Charging` 必须先给出一段足够玩家使用普通 `Space` 从顶部离开的反应时间；不能按满加力、最轻飞船或完美输入确定下限。
- `Active` 对普通敌机的有效捕获时间，至少应覆盖玩家重新瞄准并完成一次当前标准武器有效射击的时间。
- 玩家被捕获时始终保留鼠标、`W / S`、`A / D`、`Space / Ctrl`、`Q / E`、`X` 和 `Shift` 输入；不得冻结 Transform、切为 Kinematic、关闭当前运动协调器/IFCS 或把玩家强制父子绑定到墙面。
- 三面墙的主吸力保持近似水平。即使玩家暂时无法横向挣脱，也应能用 `Space` 沿墙向开放顶部移动；墙面接触摩擦不能把垂直出口变成假出口。
- `X` 只能让当前运动协调器 / IFCS 尝试制动并抵消部分吸力，不能把玩家固定在墙前；`Shift` 可以缩短脱离时间，但不能是未受损基准改装的唯一生路。
- 玩家最大受压时间设置硬上限，并在到期后进入可感知的衰减/冷却。该上限跨难度一致，不因低难度或高难度隐藏改变。
- 对不同改装记录“开始明显偏移—接触墙面—仍可沿墙移动—成功脱离”的各阶段时间，而不是只记录是否进入 Trigger。

### 5.7 防穿模、墙面卡死与可靠释放

磁场吸附目标必须是**墙体外侧的安全接触面**，不能是墙中心、墙后一点或磁力板 Transform 原点。每架飞船按自身真实碰撞体计算墙面法线方向的支撑距离，并在可见墙面前保留一小段接触余量：

```text
安全吸附距离 = 飞船所有有效碰撞体沿墙面法线的最大外伸距离 + 接触余量
安全吸附点 = 可见磁力墙表面点 - 墙面外法线 × 安全吸附距离
```

具体约束：

- 磁场 Trigger 与实体墙 Collider 分离；墙体必须有足够厚度的实体碰撞体，不能只依赖一张零厚度触发面。
- 吸力朝墙面法线收敛，并在进入接触带后逐步降低为有限保持力；不能在已经接触时继续施加满强度力把 Rigidbody 挤进墙里。
- 高速吸附阶段使用连续碰撞检测或等价的逐固定帧扫掠验证，避免一帧从墙外跨到墙内。力和最大法向速度均设置上限。
- 当前模块化飞控开始飞行时已经把 Rigidbody 设为 `ContinuousSpeculative`；磁场实现不得把它降级。若最大允许吸附速度下该模式仍不能稳定阻止穿透，再在磁场侧增加真实 Collider 扫掠，而不是提高穿透后的回弹速度掩盖问题。
- 不直接把飞船位置插值到吸附点，不关闭飞船 Collider，也不通过把目标挂到墙下实现“吸住”。主要结果始终由外力和物理解算产生。
- 为每个目标锁定一个稳定墙面与一个不会重叠的局部接触区域；多架敌机不能全部被拉向同一个点，互相把玩家或同伴挤入墙内。
- 磁力板的战斗碰撞代理应是平整、连续、与可见表面一致的低卡边面。窗框、灯带、装饰条和破碎小 Collider 不得形成飞船翼尖或武器挂架无法退出的凹槽。
- 接触时只结算一次主要撞击，持续贴墙不逐物理帧重复造成碰撞伤害。再次产生伤害需要先离开接触带并重新形成有效撞击速度。
- `Active → Cooldown` 时吸力连续衰减，随后完全清零；可以使用很小且有上限的墙面外法线分离偏置帮助解除静摩擦，但不能把飞船像炮弹一样弹射出去。
- 冷却开始后停止在三面墙之间重新分配目标。飞船应能用 `Space` 沿墙上升，或转动机头后用现有推进离开墙面。

必须保留只在异常情况下使用的卡死兜底：记录目标最后一个未与墙重叠的安全姿态；若物理解算检测到实际穿透，先计算最小分离方向，把目标移到墙外接触余量处，移除朝墙法向速度并立即恢复完整输入。该兜底不能作为每次正常吸附的实现方式，也不能额外扣血。

释放验证至少覆盖：最大合法翼展、突出侧舱/武器、轻型与重型改装、左右不对称改装、部分推进模块受损，以及多架敌机同时贴墙。磁场结束后若任何存活目标在释放宽限期内仍无法离开墙面或进入重新接敌，就判定该墙面或候选庭院无效，而不是把目标静默销毁。

### 5.8 磁场范围约束

第一版磁场只生成在原恢复区对应的三面庭院几何中，不生成中央球形磁场、单墙磁轨、道路随机磁场或与自然风叠加的复合场。这样玩家只需要学习一套稳定规则：

```text
三面墙暗蓝：关闭
→ 三面墙变黄：即将启动，从顶部离开
→ 三面墙高亮红：正在吸附
→ 红色熄灭回到暗蓝：冷却结束
```

Boss 以后可以破坏或过载三面磁力板，但第一版不做极性反转，避免已经学会的颜色和吸力方向突然失效。

### 5.9 三面磁场庭院

原恢复庭院的“三面建筑、顶部开放”结构，适合改造成磁力捕获井：

- 三面建筑立面各安装一组可见磁力板，开放顶部是玩家的主要脱离出口。
- 庭院入口外留出一段引诱航线，让玩家确认装置处于 Idle，并让追兵形成纵向队形。
- 玩家进入时三面磁力板为暗蓝色，暂时没有吸力，只触发黄色充能灯带。
- 玩家从顶部飞离捕获体积，不能只擦过入口就自动免疫后续吸力。
- 三面磁力板变为高亮红色后，追进庭院的敌机被吸向最近的磁力墙并短暂压制在那里。
- 敌机推进器继续明显喷射和挣扎，使玩家理解它们是被环境压住，而不是 AI 停机。
- 玩家可以从庭院上方或另一条射线上反打，但磁力板、楼檐或入口仍应遮挡部分射界，避免变成无风险处决。
- 捕获到期后磁场进入 Cooldown，敌机恢复姿态并重新接敌；没有被杀死的敌机不能永久留在墙上。
- 磁场结束后玩家和敌机都必须先从墙面实际分离，再恢复普通导航/追击；不能只清除“被捕获”状态而让碰撞体仍嵌在墙中。

该空间提供的是一次需要引诱、脱离和转身输出的控制窗口，不再提供修复或隐藏安全规则。

磁力同样通过环境力适配层作用于当前飞行模型，不修改飞船或敌机原有基础物理参数。所谓“压在墙上动不了”是吸力与现有推进结果之间的伪物理平衡，并设置最大持续时间，而不是冻结 Transform 或关闭 AI。

## 6. 敌我影响不必严格对称

环境规则必须可信，但不需要让玩家和 AI 得到完全相同的数值结果。

允许的差异包括：

- 玩家保留输入，敌机可以进入短暂姿态恢复状态。
- 玩家单次环境碰撞伤害有保护上限，敌机可以承受更高比例伤害。
- 玩家拥有更明确的充能提示和装置状态反馈。
- 小型敌机比玩家飞船更容易被吹飞或吸附。
- Boss 受力较小，但可能暴露模块、失去攻击角度或破坏装置。

不能接受的差异包括：

- 玩家完全不受力，但敌机被大幅吹飞。
- 敌机进入范围立即扣血，而没有真实碰撞或装置反馈。
- 玩家被吸附后完全失去控制且没有挣脱方式。
- 同为飞行器时，装置为了帮助玩家而无理由忽略玩家模块、碰撞外形和飞船质量。第一版统一不影响双方子弹与导弹属于明确的武器平衡边界，不算玩家特权。

## 7. 推荐战斗场景

### 7.1 自然街谷狂风陷阱

```text
玩家在长街上看见上游尽头出现尘墙，并听见风声增强
→ 玩家飞向中段合并街区的背风面
→ 一组现有小兵沿道路继续追击
→ 狂风从上游街口沿道路贯穿到下游
→ 楼体挡住玩家所在位置的主要风力
→ 暴露在主风道中的小兵被拍向实体楼墙
→ 小型敌机撞毁，幸存敌机失去姿态
→ 玩家从背风面转出并反打
```

如果玩家没有进入背风区，同样会被狂风推离航线；机翼可以降低操控扰动，但不能让玩家完全免疫风力或撞墙后果。

### 7.2 三面磁场庭院诱敌

```text
玩家在入口外看见三面磁力板处于待机状态
→ 可追击敌机沿入口航线追入庭院
→ 玩家穿过庭院，三面线圈依次充能
→ 玩家在满强度启动前从开放顶部飞离
→ 敌机进入捕获体积，被吸向最近的磁力墙并暂时难以移动
→ 玩家从上方转身，使用导弹、月牙或范围技能攻击受控目标
→ 磁场冷却，幸存敌机脱离墙面并重新接敌
```

如果玩家没有及时从顶部离开，也会被吸向其中一面磁力墙，需要使用推进器挣脱并承担模块碰撞风险。

### 7.3 环境状态误判

```text
玩家误判自然风的尘墙距离，或误以为磁场仍在冷却
→ 进入作用范围后狂风到达，或黄色磁场完成充能
→ 玩家来不及完全离开，被推向或吸向墙面
→ 一侧模块受到可控伤害
→ 飞船保留继续战斗和撤离的能力
```

该失败结果必须让玩家理解自己误判了环境状态，而不是认为游戏随机夺走控制权。

### 7.4 Boss 互动

- Boss 可以在玩家准备利用环境场时封锁背风区出口或磁场顶部出口。
- 自然狂风可以有限改变 Boss 的冲撞和射击方向，但 Boss 不能破坏或关闭天气。
- Boss 可以破坏三面磁力板或使其过载，但第一版不反转已经明确标识的吸力方向。
- 玩家可以诱导 Boss 进入作用范围，使其短暂丢失射界或暴露模块。
- 环境场不应无限控制 Boss，只提供有限输出窗口或模块射界。

### 7.5 小怪追击是陷阱成立的前置条件

当前项目中的普通敌机主要保持射位或在局部范围内作战，并不会像 Boss 一样持续追着玩家穿过城市。因此，“玩家把敌机引进庭院”的流程目前不能被视为已经成立：如果不先处理普通敌机的跟进逻辑，风场和磁场即使实现完整，也可能只对 Boss 生效，普通战斗中会退化成玩家自己躲避的障碍。

不建议让所有小怪无条件贴着玩家追。更适合把敌机分为战斗角色：

| 敌机角色 | 是否进入诱导路线 | 与环境陷阱的关系 |
|---|---|---|
| 追击机 / 截击机 | 会 | 主要被玩家引入风场和磁场的目标 |
| 自爆机 / 近战机 | 会，但应保持避免碰撞的基本转向 | 天然形成高压追击，可被环境反制 |
| 远程火力机 | 通常不会 | 在入口外施压，迫使玩家不能无限等待 |
| 侧翼机 | 沿平行路线或出口拦截 | 让玩家选择顶部出口时仍要判断风险 |
| 重型敌机 | 有限跟进 | 不易被完全捕获，但会被拉偏或暴露弱点 |

每个被 PCG 标记为“环境诱敌遭遇”的战斗波次，必须配置至少一组可追击敌机。建议由遭遇导演临时授予这些单位一个有边界的 Pursuit 状态，而不是永久改变所有敌机：

1. 玩家进入装置前的引诱航线，并且敌机已经发现玩家。
2. 选取距离合适、机动能力足够的少量敌机进入 Pursuit。
3. 它们沿真实可飞行路径追踪玩家或玩家最后可见位置，并允许穿过庭院入口。
4. 追击具有最大距离、最大持续时间和导航失败回退，不能追到城市外或永远脱离原战区。
5. 玩家穿过装置、丢失视线或装置完成一次循环后，幸存单位进入重新接敌，而不是原地悬停。

Pursuit 需要通过敌机的行为表现出来：机头转向玩家、推进器明显加速、队形由横向射击转为纵向跟进，并伴随接近音效。不要用信息栏文字告诉玩家“敌机现在会追击”。

如果某次生成的敌人编组没有任何兼容 Pursuit 的单位，则 PCG 必须执行以下一种处理：

- 不把该装置计作本次遭遇的战斗解法，只作为关闭状态的地标或普通通行空间。
- 从本次原有敌人编组中重新分配少量兼容单位为追击角色，保持敌人总数、生命、伤害和波次预算不变。
- 拒绝这次“环境场 + 敌人编组”组合，把环境战术遭遇安排到包含兼容追击单位的其他节点。

不能生成一个只有远程敌机、却要求玩家完成“把敌人引进庭院”的战斗目标。

### 7.6 陷阱必须真正有用

风场和磁场不是只播放一次的场景演出，也不是玩家通常应该绕开的纯危险区域。每次被标记为环境战术遭遇时，系统必须保证玩家存在一次实际可完成的利用机会：

- 自然风遭遇中，至少一部分当前波次的小型敌机能够沿主风道追击玩家，并可能被吹向已验证的实体墙面。
- 三面磁场遭遇中，至少一部分当前波次的小型敌机能够穿过庭院入口，并在玩家顶部脱离后进入磁力捕获体积。
- 敌机不能在玩家接近陷阱时统一停止追击，也不能凭借隐藏信息提前绕开尚未启动的环境场。
- 敌机可以在看到尘墙、黄色充能灯或实际受力后尝试制动和修正，但小型追击单位不应总能完美逃脱。
- 成功利用自然风应至少造成小兵撞毁、撞伤或明显失去姿态；成功利用磁场应至少提供一次足够玩家完成有效攻击的控制窗口。
- 陷阱结束后，幸存敌机恢复现有战斗逻辑并重新接敌，不能永久失去目标。

为了保持现有难度曲线，AI 修改只改变一部分现有敌人的空间行为和追击路径：

- 不增加敌机数量，不改变波次预算，也不额外生成“专门送进陷阱”的敌机。
- 不改变敌机生命、武器伤害、命中率、攻击冷却和当前难度倍率。
- Pursuit 不让敌机获得额外速度或超出当前机动能力，只允许它们使用现有移动能力继续跟进玩家。
- 玩家完全不利用陷阱时，遭遇仍按当前基础强度正常进行。
- 玩家正确利用陷阱时获得局部优势，这是地图知识和操作选择的回报，不通过后台强化剩余敌人抵消。

### 7.7 玩家真实操作合同

环境陷阱必须使用项目当前的 `RobocraftControlFrame` / 键鼠输入完成；兼容旧 IFCS 链路时也沿用同一组键位。不能在文档中假设一个并不存在的“抗风”“挣脱”或“触发陷阱”按键。

| 玩家意图 | 当前真实操作 | 自然风中的作用 | 三面磁场中的作用 |
|---|---|---|---|
| 保持或改变机头 | 移动鼠标，通过当前 Pilot Aim / 准星朝向控制机头；旧 IFCS 链路继续使用其虚拟摇杆 | 对准街道、观察尘墙并修正偏航/俯仰 | 离开顶部后转头瞄准被捕获敌机 |
| 前进 / 后退 | `W / S` | 控制沿街距离、进入或退出诱敌位置 | 沿入口进入，或在尚未满功率时退出 |
| 横向平移 | `A / D` | 在与街道基本对正时切入合并楼体背风面，或从楼角探出反击 | 选择庭院入口一侧或离开墙面法线 |
| 上升 / 下降 | `Space / Ctrl` | 越过低矮遮挡或避开贴地乱流，但不能无视高楼封锁 | `Space` 是开放顶部的主要脱离操作，吸力主方向不得封死垂直出口 |
| 横滚修正 | `Q / E` | 修正阵风引起的滚转，机翼和垂尾改装降低持续修正负担 | 被不对称墙力拉偏后恢复姿态 |
| 制动 / 悬停保持 | `X` | 当前模块化飞控使用幸存执行器尝试制动并保持位置，在背风面降低冲出掩体或撞楼的风险 | 减少穿过庭院时的过冲，等待追兵进入；吸力超过权限时仍会漂移 |
| 短时加力 | `Shift` | 快速横穿主风道或从楼角撤回 | 提高顶部脱离容错 |
| 紧急闪避 | `F + W/A/S/D` | 可选地快速离开主风道或楼角火线 | 可选地在满吸力前扩大与墙面的距离；冷却中仍必须有普通操作生路 |
| 自由观察 | `Alt` | 可选地观察上游尘墙而不改变机头 | 可选地确认三面磁力板颜色 |

这些操作需要遵守以下边界：

- 第一版不增加环境专用按键，也不要求玩家一边射击一边额外按交互键维持装置。
- 当前模块化流程在改装界面选择街机/标准核心辅助，战斗中不要求临时切换模式；环境陷阱不能依赖一个没有显示在该流程里的模式切换操作。
- 若旧 IFCS 链路也进入同一城市，默认 `Coupled` 必须能够完成陷阱，不能要求玩家切到行星飞行不可用的 `Direct`。
- `Shift` 加力是提高容错和缩短暴露时间的选择，不是标准飞船成功逃生的硬门槛；即使加力储备已耗尽，正确且及时的普通输入也应存在出路。
- `X` 只表示当前飞控用幸存执行器尝试制动、悬停或保持位置，不是把 Rigidbody 固定在世界中。风力或磁力超过当前推进权限时，按住制动仍会漂移，这种漂移必须通过运动和推进反馈表现出来。
- `F` 闪避、自由观察以及旧 IFCS 的虚拟摇杆归中/调速都可以帮助熟练玩家，但陷阱不能要求闪避已冷却、必须按中键归中或必须先调速才能通过。
- 玩家已经在瞄准和射击，标准利用流程不应持续要求鼠标转向、`Q/E`、`A/D`、`Space/Ctrl`、`Shift` 和 `X` 同时输入。关键逃生阶段优先限制为“一个方向输入 + 可选加力”，姿态修正留给前后缓冲阶段。

自然街谷狂风的标准操作闭环应当是：

```text
玩家在顺着街道的常规接近航向上看见上游尘墙
→ 用 A / D 切入合并楼体背后的弱风区，用 W / S 调整与楼角的距离
→ 必要时用 X 在背风区稳定，而不是在主风道中获得无条件锚定
→ 追击小兵沿街进入主风道并被推向实体墙
→ 玩家用 A / D 从楼角探出，鼠标重新对准，完成反击
```

三面磁场庭院的标准操作闭环应当是：

```text
暗蓝关闭时，玩家用 W 从入口穿入，追击小兵跟进
→ 磁力板转黄并开始充能
→ 玩家保持当前机头，用 Space 从开放顶部上升；Shift 只用于提高容错
→ 磁力板转红并把仍在庭院内的小兵吸向三面墙
→ 玩家用鼠标转头、A / D 选择射界并攻击受控目标
```

玩家误判后的恢复也必须对应现有操作：自然风中优先允许玩家把机头转向安全航线并靠当前侧移/推进权限进入背风区；磁场中保留主要为水平方向的吸力，使 `Space` 顶部脱离始终可理解。不能在玩家被捕获后禁用输入，再用隐藏倒计时决定是否放走。

### 7.8 街机与标准模式分别设计

项目当前的 `VehicleCoreAssistMode.Training` 在界面显示为“核心辅助：街机”，`VehicleCoreAssistMode.Standard` 显示为“核心辅助：标准”。环境场应分别调校这两种操控体验，但不要复制两套 PCG、视觉状态或敌人难度。

两种模式共享的不变量：

- 自然风从哪端吹向哪端、建筑如何遮挡、磁场暗蓝/黄/红状态、装置实际 Active 周期与冷却周期保持一致。
- 敌机、Boss、碰撞墙、追击编组和陷阱收益保持一致，不因玩家操控模式改变敌人数量、生命、伤害或 AI 反应时间。
- 总质量、质心、惯量、推进器方向与受损状态在两种模式都生效；街机只能压缩极端差异，不能把改装影响清零。
- 防穿模、单次碰撞伤害上限、释放兜底和最大合法飞船外形校验属于安全规则，两种模式完全一致。

| 项目 | 街机模式 | 标准模式 |
|---|---|---|
| 操作目标 | 一次明确方向输入就能执行战术，姿态和旧方向漂移由辅助处理大部分 | 玩家主动管理漂移、姿态、制动和推进方向 |
| 风场反馈 | 仍会产生可见位移和机身晃动，但环境补偿、消漂与姿态恢复更强 | 更完整保留质量、惯量、气动面和推进布局造成的位移与转矩 |
| 松开移动键 | 现有街机定点/急停辅助尝试抵消一部分环境力，但受当前幸存推进权限和环境补偿上限约束，不能在狂风中绝对悬停 | 不额外获得街机定点力，只依靠标准模式当前模块能力和玩家输入 |
| 磁场顶部脱离 | 黄色充能后按住 `Space` 即为主操作；辅助优先保证垂直意图和基本姿态，`Shift` 可选 | 同样以 `Space` 为主，但玩家可能需要用鼠标或 `Q / E` 管理吸附造成的姿态偏移 |
| 被吸墙后的移动 | 自动压低朝墙法向速度，优先把 `Space` 解释为沿墙向顶部移动，并在冷却时提供更明显但受限的分离帮助 | 只保留必要的接触降力与防卡死兜底，脱离主要依赖当前方向推进权限和玩家转向 |
| 有效受压时间 | 玩家有效受压时间上限较短；即使磁场仍显示红色，正确的单方向输入也应较快恢复移动 | 允许较长的受力对抗，但始终保留输入，且不得超过统一的玩家控制上限 |
| 改装差异 | 质量、推进和机翼仍有影响，但使用较窄的易感度上下限，避免新手改装因一个缺口完全无法挣脱 | 使用较宽的连续范围，让轻重、惯量、翼面和推进布局差异成为明确操作后果 |

街机模式的环境补偿必须遵守当前实现原则：玩家移动意图优先，消漂、定点与姿态修正使用剩余权限；所有辅助仍受安装模块、核心辅助上限和推进损伤限制。不能在风场或磁场中临时生成一股与改装无关的无限反向力。

标准模式也不能被设计成“更容易卡死”：它可以更难稳定和脱离，但墙面接触降力、连续碰撞、顶部可达、Active 时间上限与异常分离兜底仍然存在。操作复杂度与物理故障必须严格分开。

磁场红色 Active 的世界持续时间建议两种模式一致；区别来自玩家侧的辅助分配、有效受力倍率上限和最大受压时间。这样颜色不会在两个模式中表达不同事实，街机玩家又能更早靠操作恢复移动。

## 8. PCG 生成约束

风场和磁场不能只生成一个 Trigger Bounds；建筑、道路、出口、遮挡体和受力方向必须共同支持对应战斗行为。

### 8.1 通用约束

- 作用范围不能覆盖玩家出生点。
- 必经路线不能在无提示情况下被自然风或磁场直接封死。
- 至少存在一个可脱离方向，或装置本身具有明确关闭周期。
- 玩家在进入满强度区域前应能观察至少一种状态提示。
- 环境场产生的主要受力方向必须与真实建筑碰撞面相匹配。
- 预计撞击墙面必须支持敌机和玩家的真实碰撞检测。
- 不能把目标推入地图外、无碰撞区域或无法回收的导航死区。
- 高速进入时仍应保留合理反应时间。
- 风力或磁力未生效时，该空间仍必须可以正常飞行通过。
- 预警时间不使用脱离飞船性能的固定常量，应至少覆盖基准改装在不使用 `Shift` 时完成主要逃生输入的时间，并增加观察与输入延迟余量。
- 入口、背风区、楼角与顶部出口按允许参战飞船的真实包围盒和翼展验证，不能只用未改装船体尺寸。
- 标准操作路径必须分别在当前街机和标准核心辅助下成立；旧 IFCS 兼容路径在默认 `Coupled` 成立，不依赖 `Direct`、巡航、中键归中或战斗中临时切换飞控模式。
- 装置提示和主要出口尽量位于玩家常规前向视野内；不能要求玩家持续自由观察后方，同时完成近距离战斗输入。
- 同一候选点必须分别通过街机与标准操作剖面验证。街机验证“一次主要方向输入即可脱离”，标准验证“模块驱动下能够抵抗并恢复”；任一模式出现必然卡死都不能发布。

### 8.2 数量、间距与激活预算

自然狂风和三面磁场是特殊战术标点，不是覆盖全城的常驻效果。第一版 PCG 建议采用明确预算：

- 只有具备完整“观察区—引诱区—作用区—脱离区—反击区”的候选点，才能生成环境场。
- 环境场节点不超过可用战斗空间节点的约 `15%`；具体比例后续按地图尺寸调整，但不能按空地数量无限填充。
- 同一条主要任务路线建议至少间隔 `3` 个普通战斗或航行空间，才允许再次出现环境场。
- 同一战斗口袋内最多存在 `1` 种主环境场；第一版不把自然风与磁场叠在同一空间。
- 两个环境场的有效范围不能重叠，中心间距至少大于两者最大作用半径之和，并额外保留观察距离。
- 相邻候选点不连续生成同类环境场，避免玩家感觉整座城市都在刮风或到处存在磁力。
- 玩家当前可感知的遭遇范围内，默认最多只有 `1` 个环境场进入 Charging 或 Active；远处自然风保持平静，远处磁场保持 Idle、Cooldown 或 Disabled。
- 主线必经狭窄通道不连续放置环境场；高风险环境场优先放在可选支路、庭院或带旁路的节点。
- Boss 战的环境场使用独立预算和人工规则，不与普通 PCG 配额相加后随机堆叠。

环境场的“未生效”是正常状态。自然风由可学习的天气周期和遭遇时机决定，磁场由入口感应与充能决定，不能全场同时随机开关。

### 8.3 风场候选点验证

- 候选点是一条具有明确上游尽头和下游尽头的长街，不依赖机械喷口。
- 生成数据中存在明确自然风入口、主风向、有效街谷范围和下游终点。
- 上游必须有尘墙、云层、雾带或轻质碎屑预兆的可见空间。
- 从观察区能够根据街道朝向、尘雾、悬挂物和环境粒子判断风从哪边吹向哪边。
- 风向在单次启动期间保持稳定，不逐帧随机摆动。
- 中段至少存在一个由合并街区构成的实体楼体遮挡，并在背风面生成足够玩家机动的弱风区。
- 常规接近航向应与长街方向基本对正，使玩家能用现有 `A / D` 横移直观进入背风面，而不是必须先完成大角度掉头或精确倒飞。
- 背风区至少允许最大合法玩家飞船完成制动、姿态恢复和一次楼角探出；`X` 制动不能被当成完全抵消风力的隐形安全规则。
- 风力遮挡检测必须使用真实楼体空间，不能让主风力穿过合并建筑继续保持满强度。
- 楼角与风区边界使用连续衰减，避免风力瞬间跳变。
- 下游或侧前方至少存在一个经过验证的实体撞击面，小型追击敌机可能被风拍到墙上。
- 风向不会把完整玩家飞船一次推入必死夹缝。
- 敌机撞墙后存在脱离、死亡或回收路径。
- 没有符合长街、遮挡楼体、背风区和撞击面条件的候选点时，不生成自然狂风战术节点。

### 8.4 磁场候选点验证

- 三面磁力板在玩家进入前可以被观察。
- 每个吸附方向都有对应的可见墙面磁力板。
- 三面磁场庭院必须有开放顶部出口、入口引诱距离和顶部反击位置。
- 第一版磁场候选点必须来自原恢复庭院的三面围合模板，不接受普通道路和随机空地。
- 三面磁力板关闭时统一显示暗蓝、充能时统一显示黄色、开启时统一显示高亮红色。
- 玩家从入口进入、向顶部脱离的路径不能与建筑檐口或不可见碰撞体冲突。
- 黄色充能持续时间应大于基准改装仅使用普通 `Space` 上升离开捕获高度所需时间并保留反应余量，不能以满加力状态作为唯一通过标准。
- 三面墙的主要吸力保持近似水平，不能用额外向下分量抵消开放顶部的战术意义。
- 吸附中心周围有足够空间容纳预期敌机数量。
- 聚集后的敌机不会互相穿透或永久卡死。
- 三面磁力板必须为目标选出稳定的主要吸附面，不能让合力造成高频抖动。
- 三面墙分别具有与可见磁力板对齐的平整实体碰撞代理、墙外安全接触带和足够厚度；磁力目标点不得位于墙体内部。
- 墙面为并发目标提供多个不重叠的吸附区域，并预留玩家最大合法外形；不能让多架敌机把玩家挤进墙或建筑夹角。
- 墙面前方、沿墙向上的释放走廊和冷却后的外法线分离空间，不得存在会勾住翼尖、武器或侧舱的小型凹凸 Collider。
- 候选点按最大合法翼展/外形生成静态安全余量，运行时再按当前飞船真实 Collider 计算精确吸附距离。
- 从最大允许进入速度到墙面的距离，必须足以通过受限磁力与连续碰撞解算停在墙外接触带；不能依赖穿透后传送修正作为正常流程。
- Active 结束后，玩家与所有存活敌机都能从锁定墙面分离并进入合法航行空间；释放路径验证失败时拒绝该候选点。
- 玩家即使推进模块部分受损，也仍存在至少一种脱离可能。
- 磁场边界不能产生速度或加速度瞬间跳变。

### 8.5 遭遇与 AI 兼容性验证

- 诱导入口必须连接普通敌机能够实际飞行的导航空间，而不只是玩家能穿过的缝隙。
- 追击敌机从发现玩家到进入作用范围的时间，必须小于其 Pursuit 超时。
- 至少一类当前生成的敌机拥有进入磁场庭院或自然风主街的追击能力。
- 远程敌机在陷阱外的射线不能覆盖玩家全部脱离出口，否则玩家没有战术选择。
- 环境场结束后，幸存敌机拥有脱离吸附面或撞击面、恢复姿态和重新接敌的路径。
- 若以上条件任一不成立，该候选点不能被计为依赖诱敌的战术机会。
- Pursuit 必须从当前波次已有敌机中分配，不能通过额外补怪满足兼容性。
- AI 兼容性调整不得改变当前难度的生命、伤害、数量、波次节奏和难度倍率。

## 9. 城市连续性与地图边界视觉

### 9.1 当前问题

当前城市场景在部分道路、高处和城市边缘视角下，会直接露出可玩地面的终点、空白平面或楼群突然中断的位置。玩家看到的是一块被摆放了建筑的战斗场景，容易产生“在孤岛上战斗”的感觉，而不是身处一座向远方继续延伸的城市。

该问题不要求扩大真实战斗地图，也不要求为远景制作高模。目标是把“可玩边界”和“视觉边界”分开：

```text
可玩城市核心
→ 近景延续层：低模建筑与道路，提供真实视差
→ 中景城市层：成片体块，遮住地面边缘
→ 远景天际线：极低模轮廓与灯光材质
→ 距离雾和天空：隐藏最后的视觉终点
```

玩家不能飞到视觉城市，但在可玩区域的任何常见观察点，都应该继续看到楼群、道路结构和城市灯光，而不是看到地图切口。

### 9.2 优先复用现有材质

第一版不需要新增一套远景美术资源，可以用现有建筑和道路材质完成：

- 使用简单长方体、阶梯体和少量屋顶轮廓组成远景楼体，复用现有建筑外墙、窗户、自发光窗格、金属和屋顶材质。
- 道路延续部分复用现有路面、路肩和城市地面材质，不给远景道路生成完整细节。
- 远景窗户优先依靠现有自发光材质，不为每扇窗创建真实灯光。
- 同类建筑尽量共享材质；需要变化时优先使用材质参数或有限的现有材质组合，不复制大量近似材质实例。
- 近景延续层可以复用现有建筑的低细节部分；中远景只保留体块、楼顶轮廓和发光窗面。
- 远景不需要室内、可破坏模块、墙面受击特效、磁场、风场或其他战斗组件。

现有材质的细节即使在远处看不清，也能让背景楼群与可玩楼群保持相同的颜色、反射和夜景语言，比完全不同风格的天空盒城市更自然。

### 9.3 三层城市壳

#### 近景延续层

位于玩法边界外侧，是最重要的一层：

- 使用真正的简化三维楼体，保证玩家横向飞行和升高时能够看到视差。
- 延续可玩区现有街道朝向、街区尺度和建筑基线，不能突然变成与内部网格无关的一圈模型。
- 边界道路在视觉上继续进入后续街区、转弯、下穿或被前方建筑遮挡，不能在地面边缘直接截断。
- 建筑可以低模，但轮廓高度要有变化，不能像围墙一样等高排列。

#### 中景城市层

中景负责遮住绝大多数裸露地面：

- 用成组的楼体块、裙楼、工业设施、高架桥轮廓和少量高塔构成城市密度。
- 细节主要依赖现有材质与发光窗面，不生成阳台、管线等小结构。
- 楼群之间保留远处道路缝隙和高低节奏，但任何缝隙后面仍应有下一层城市或雾，而不是空白。

#### 远景天际线

远景只负责形成“城市还在继续”的轮廓：

- 使用极低面数楼体、合并后的楼群或仅在最远距离使用的建筑轮廓片。
- 天际线不能是一圈等间距、等高度的柱子；应有低区、密集区、地标高塔和大片中层楼群。
- 极远建筑可以降低材质种类、关闭实时阴影，并逐渐融入与天空颜色一致的距离雾。
- 二维轮廓片只适合最远一层。由于本项目允许空中移动，近景和中景不能全部使用永远朝向相机的平面，否则升降时会失去可信视差。

### 9.4 地面边界的处理

只加远处高楼还不够；如果玩家能从楼群之间看到地面平面突然结束，孤岛感仍然存在。

- 在玩法地面之外增加只用于渲染的城市地面延伸层，复用现有道路、城市底座、屋顶或深色工业地面材质。
- 视觉地面必须延伸到中远景楼群下方，最后在雾中结束，不能紧贴玩法 Bounds 截断。
- 所有通向边界的主要道路都要生成视觉续段，优先在远处转弯、进入下穿通道、穿过楼群或被高架结构遮挡。
- 不建议在每条道路尽头统一摆放路障或高墙，这会暴露“这里就是关卡边缘”。
- 从高空向下看时，城市地面和楼群轮廓不能形成清楚的正方形或圆形外框；外层街区边缘应不规则错开。

### 9.5 空战视角的特殊要求

地面游戏只需要处理水平视线，但空战玩家会快速升高，因此远景必须同时通过水平和俯视检查：

- 视觉壳层尺寸应依据玩家最高可达高度、相机最远视距和最大俯视角计算，而不是只按地面道路视角估算。
- 玩家升到当前允许的最高战斗高度时，仍不能越过近景楼群直接看到城市底板终点。
- 外层楼群需要有足够的横向厚度；只在边缘摆一排高楼，会在高空立刻暴露后方空白。
- 开阔道路正前方、楼顶上方和 Boss 战高空位置属于高优先级遮蔽方向。
- 距离雾负责隐藏最后一层的终点，但不能用过浓的雾直接遮住当前战斗目标和建筑战术关系。

### 9.6 PCG 生成流程

城市连续性壳层应在可玩 PCG 城市完成以后单独生成，不参与战斗布局：

1. 生成可玩城市、主要道路和真实战斗空间。
2. 取得玩法边界、道路出口、玩家可达高度和重要观察点。
3. 沿原有道路方向向边界外生成近景视觉续段。
4. 在裸露视线方向生成中景建筑簇，优先遮住地面断口。
5. 生成更远的低模天际线，并用距离雾衔接天空。
6. 从出生道路、主要战斗道路、楼顶路线、Boss 高度和最高可达高度进行可见性验证。
7. 若任何采样视线命中空白地面或视觉壳层终点，则补充楼群、调整高度或延长视觉地面，而不是扩大真实碰撞城市。

视觉壳层可以继续使用同一城市 Seed，使道路朝向、建筑密度和地标分布稳定；但它应拥有独立预算，不能因为生成大量远景而挤占真实战斗节点预算。

### 9.7 PCG 约束与性能边界

- 视觉建筑必须位于玩法边界之外，并与玩家最大可达位置保持安全距离。
- 视觉壳层不生成 Collider、Rigidbody、NavMesh、敌人出生点、任务点或可破坏模块。
- 子弹、锁定、敌机寻路、Boss 攻击和 LOS 判断不得把视觉建筑当成真实战斗目标或遮挡体。
- 近景层使用低模三维建筑；中远景优先合并网格、GPU Instancing 或项目已有的批处理方案。
- 中远景关闭不必要的实时阴影、反射探针更新、粒子和脚本 Update。
- 不直接复制完整可玩建筑 Prefab 到远景；若复用 Prefab，必须有剥离战斗组件和高成本细节的视觉版本。
- 外层建筑沿街区生成，而不是围绕地图中心排成规则圆环。
- 同一建筑轮廓不能长距离连续重复；高度、宽度、朝向和现有材质组合应在受控范围内变化。
- 不能用单栋极高建筑遮住所有缺口，也不能形成一圈不可解释的摩天楼围墙。
- 视觉层的密度应由可见性缺口驱动：优先填补玩家实际能看见边界的方向，不要求在完全被遮挡的位置浪费同等预算。
- 背景生成失败时不能影响真实城市生成；应回退到较简单的楼群簇和地面延伸层。

### 9.8 第一版低成本方案

第一版先验证“城市不再像孤岛”，不追求无限城市：

1. 复用现有外墙、窗户、道路和屋顶材质，制作少量参数化低模楼体。
2. 在可玩边界外生成至少两层有厚度的三维建筑簇，而不是一排围墙。
3. 延长所有暴露的道路和城市地面，让它们在远景建筑与雾中消失。
4. 在最远处加入低成本天际线层，并关闭碰撞、AI、阴影和战斗逻辑。
5. 从高空与道路分别截图验证，再决定是否需要更复杂的 Impostor 或动态重定位方案。

第一版不建议直接做跟随玩家移动的无限背景城市。固定视觉壳层更容易保证视差、道路连续性和不穿帮；只有在固定壳层无法覆盖当前最大飞行高度时，再考虑相机相对的极远天际线。

### 9.9 验收标准

1. 从玩家出生的大路向任意开放方向看，不再看到地面突然结束或楼群后方完全空白。
2. 从主要道路、庭院出口、楼顶航线和 Boss 战常用高度观察，视觉城市都能延续到雾和天际线。
3. 玩家横向飞行和升降时，近景与中景背景具有可信视差，不像贴在天空上的一张图。
4. 通往边界的道路在视觉上进入后续街区、转弯或被建筑遮挡，而不是直接断头。
5. 从最高可达高度俯视时，看不出玩法地面的规则方形、圆形或清楚外轮廓。
6. 背景城市与可玩城市使用一致的现有材质语言，但能明显减少渲染、物理和脚本成本。
7. 子弹、锁定、敌机导航和 Boss 攻击不会与视觉城市产生错误交互。
8. 不依赖极浓雾遮住近处战斗；即使暂时关闭雾，近景建筑簇仍能遮住主要地面断口。

## 11. 验收重点

后续实现至少应验证以下问题：

1. 玩家能否仅靠装置动作、声音和环境粒子判断关闭、充能、开启与冷却。
2. 玩家经过关闭装置后，延迟启动是否既有意外感又保留反应机会。
3. 敌机是否受到真实力并因真实建筑碰撞而受伤。
4. 敌机撞墙后是否会死亡、恢复姿态或重新接敌，而不是永久卡住。
5. 玩家是否受到明显风力或磁力，而不是获得隐形豁免。
6. 完整玩家飞船是否能承受一次标准环境撞击而不立即爆炸。
7. 玩家受伤是否落在实际受撞模块上。
8. 玩家推进模块受损时是否仍有最低限度的脱离方式。
9. 风场和磁场是否真正改变敌人队形与射击角度，而不只是播放特效。
10. 装置关闭后，该区域是否仍是合法、可读的普通航路。
11. Boss 是否能合理抵抗、利用或破坏装置。
12. 不看区域名称和 HUD 说明时，玩家是否仍能解释刚才发生了什么。
13. 玩家能否在风场启动前明确指出风源、风向以及预期撞击面或出口。
14. 三面磁场庭院是否能让玩家从顶部脱离，并把追入的敌机稳定吸向具体磁力墙。
15. 普通遭遇是否确实生成了会跟进的敌机，而不是只有 Boss 能完成诱导流程。
16. Pursuit 敌机是否通过真实路径进入装置，并在超时、导航失败或装置结束后正常回退与重新接敌。
17. 同一可感知区域是否避免多个风场和磁场同时启动。
18. 连续游玩时，普通城市空间是否仍占主体，环境场没有过密、重复或全场随机启动。
19. 自然狂风是否从长街一个明确尽头吹向另一个尽头，而不是来自机械喷口或无来源的 Trigger。
20. 合并街区楼体是否真正衰减或挡住风，并形成足够玩家机动的背风区。
21. 小型追击敌机是否能被自然风真实拍到楼墙，并在超过碰撞阈值时撞毁。
22. 健康机翼是否明显降低风造成的操控扰动，同时没有让玩家完全免疫风力。
23. 环境力接入前后，未处于风场或磁场中的飞船基础操控是否保持一致。
24. 三面磁场是否严格使用暗蓝关闭、黄色充能、高亮红色开启的统一颜色规则。
25. 玩家不使用陷阱时，敌人数量、生命、伤害和波次节奏是否与当前难度保持一致。
26. 玩家使用陷阱时，是否真的获得小兵击杀或有效输出窗口，而不是只有特效和理论设计。
27. 玩家是否只用当前真实键位就能完成“进背风区—诱敌—探出反击”和“进入庭院—`Space` 顶部脱离—转身攻击”，没有新增隐藏交互键。
28. `X` 制动在风场和磁场中是否只调用当前推进权限抵抗，而没有把玩家固定在世界坐标。
29. 轻型与重型改装受到同一风力/磁力时是否产生连续、可解释的不同位移；重型改装是否同时保留原有机动和碰撞动量代价。
30. 质心、惯量、推进方向、推进损伤、模块缩放、机翼/垂尾面积是否读取当前真实装配结果，而不是使用固定玩家抗性。
31. 街机模式是否能用一个主要方向输入完成标准逃生，且仍能明显感觉到环境力；标准模式是否保留更完整的漂移、姿态和改装差异。
32. 街机与标准模式是否共享风向、磁场颜色、世界 Active 周期、敌人效果和难度数值，避免同一视觉提示表示两套规则。
33. 最大合法翼展、突出模块和不对称改装被吸到三面墙时，所有真实 Collider 是否停在墙外而没有穿模、夹入窗框或卡在墙角。
34. 多架敌机与玩家同时被吸附时，是否被分配到不重叠的接触区域，而不是互相挤进墙体。
35. 磁场从 Active 进入 Cooldown 后，玩家与所有存活敌机是否在释放宽限期内实际离开墙面；随后敌机是否正常重新接敌。
36. 磁场接触阶段是否只结算一次主要撞击，持续贴墙没有逐物理帧重复伤害。
37. 正常吸附是否依靠外力、连续碰撞和接触降力完成，而不是依靠每次传送；异常穿透兜底是否能无额外伤害地恢复到最后安全姿态。
38. 街机和标准两种模式下，黄色充能时间是否都允许未使用 `Shift` 的基准合法改装从顶部脱离。

## 12. 当前待定问题

- 自然狂风由城市天气系统、局部风暴还是关卡事件调度；无论来源如何，都不使用机械风装置。
- 三面磁场属于城市基础设施、敌方设施还是中立设施。
- 玩家是否能主动射击或交互控制装置。
- 装置启动规律是固定可学习，还是由 Seed 在有限模板中选择。
- 后续版本是否把磁场扩展到实体弹；第一版明确只影响飞行器，暂不改变现有武器平衡。
- 玩家撞墙伤害保护采用单次上限、短暂无伤、递减还是组合方案。
- Boss 破坏装置后，是永久关闭、方向反转还是产生一次失控脉冲。
- `15%` 的环境场节点预算和至少 `3` 个普通空间的间隔，是否适合当前 PCG 城市实际尺寸。
- 自然风与磁场是否可以在同一遭遇组合；第一版明确不组合，以保证规则可读。
- 哪些现有小怪适合直接获得 Pursuit，哪些需要保留远程射位职责。
- 每次诱敌遭遇至少需要多少架追击机，才能既让陷阱可用又不形成贴脸围堵。

## 13. 第一版实施优先级建议

1. 移除恢复庭院的安全区与压力降低语义。
2. 把环境场接入城市战斗当前使用的环境提供器、力账本与运动协调器，先证明场外飞行手感完全不变，且不覆盖重力与现有气动力。
3. 建立基于当前总质量、质心、惯量、推进权限、气动面和碰撞外形的改装响应，并分别建立街机/标准玩家操控剖面。
4. 从现有波次中让一种普通敌机具备有限 Pursuit、路径失败回退和重新接敌，证明小怪能够被玩家诱导，同时不增加敌机数量或数值。
5. 用固定布局制作三面磁场庭院，先完成暗蓝关闭、黄色充能、高亮红色开启和 `Space` 顶部脱离闭环。
6. 完成磁力墙外安全接触点、稳定吸附面、并发接触区域、连续碰撞、接触降力、冷却释放和最后安全姿态兜底，再允许磁场进入 PCG。
7. 接入玩家局部模块碰撞伤害上限，确认轻重、最大翼展和受损改装被吸墙后都不会一次爆炸或永久卡死。
8. 实现一条从街道一端吹向另一端的自然狂风长街，以及由合并街区楼体形成的背风区。
9. 接入机翼伪物理抗风、敌机撞击建筑伤害和小型敌机撞毁结果。
10. 分别在街机与标准模式验证玩家确实能用两种陷阱获得击杀或输出窗口，再接入 PCG 密度、间距和敌人编组校验。
11. 最后接入 Boss 对自然风和三面磁场的有限抗性与互动。

第一版应优先证明以下体验成立：

> 玩家在长街看见上游尘墙，利用合并街区楼体进入背风面；追击小兵被自然狂风拍到楼墙上撞毁。另一场战斗中，玩家看见三面磁力板由暗蓝转黄，用 `Space` 从顶部脱离；磁力板转为高亮红色并把追兵吸向墙外的安全接触面，玩家转身获得输出窗口。街机模式用更少的输入完成同一战术，标准模式更完整表现质量、惯量、推进布局和气动差异；两者的环境视觉、敌人规则和难度数值保持一致。磁场结束后所有存活单位都能从墙面真实分离并重新行动。
