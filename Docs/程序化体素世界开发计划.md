# 程序化体素世界开发计划

> 目标：实现**程序化生成 + 可行走 + 可破坏**的地形/星球系统。  
> 原则：**先做平地，再做星球；先固定范围，再做流式加载；每阶段验收通过后再进入下一阶段。**

---

## 重要说明

**不存在「一定零 Bug」的方案。** 本计划采用业界验证最久的方块体素路线，通过**锁死范围、锁死数据结构、分阶段验收**将风险降到最低。每个阶段都有明确测试清单，未全部通过则**不得进入下一阶段**。

---

## 总原则

1. **先做平地，再做星球**（星球是平地系统的延伸）
2. **先做固定大小世界，再做无限流式加载**
3. **先用简单挖方块，再做平滑地形（Marching Cubes / SDF）**
4. **玩家使用 CharacterController，不使用 Rigidbody**
5. **体素数组是唯一数据源**，禁止直接修改 Mesh 绕过体素数据

---

## 技术选型

| 模块 | 选择 | 原因 |
|------|------|------|
| 体素形状 | 轴对齐方块 | 数据结构简单，挖/放逻辑明确 |
| 网格算法 | Naive 外露面剔除 | 比 Greedy / Marching Cubes 边界 Bug 少 |
| 世界范围（阶段 1） | 固定 64×64×64 | 排除流式加载类 Bug |
| 程序化生成（阶段 1） | 2D 高度图 + 实心填充 | 最稳定，不易出现空洞/浮空 |
| 玩家控制 | CharacterController | 行走稳定，不与物理引擎冲突 |
| 存档 | 只存被修改过的 Chunk | 体积小、逻辑清晰 |

### 前期明确不做

- 球形星球（第四阶段才做）
- 无限地图流式加载（第三阶段才做）
- Marching Cubes / SDF 平滑地形
- Rigidbody 玩家
- GPU 程序化生成
- 多人同步
- 物理塌方（挖完悬空是正常现象）

---

## 整体架构

```
世界种子
    ↓
噪声生成器（VoxelTerrainGenerator）
    ↓
Chunk 体素数据（byte[]，唯一真相源）
    ↓
网格生成（VoxelMesher，Naive 外露面）
    ↓
Mesh + MeshCollider（可行走碰撞）
    ↓
玩家挖掘 → 修改体素 → 标记 Chunk Dirty → 重建网格
    ↓
存档（只存被改过的 Chunk）
```

---

## 类结构（固定，勿随意改动）

| 类名 | 职责 |
|------|------|
| `VoxelWorld` | 管理所有 Chunk；世界坐标 ↔ 体素坐标转换 |
| `VoxelChunk` | `byte[]` 体素数据；生成；重建 Mesh |
| `VoxelMesher` | Naive 外露面网格生成（无状态纯函数） |
| `VoxelTerrainGenerator` | 纯函数：坐标 → 体素类型（无状态） |
| `VoxelDigTool` | 射线检测；挖/放体素 |
| `VoxelSaveSystem` | 只存修改过的 Chunk |
| `PlanetGravity` | **第四阶段才加**：指向地心的重力 |

**规则：每个类只做一件事。所有挖/放只改体素数组，改完标记 Chunk Dirty，不允许直接改 Mesh。**

## 第一阶段：平地可走可挖（必达）

### 世界规格（写死）

```
Chunk 大小：16 × 16 × 16（4096 体素/Chunk）
世界范围：4 × 4 × 4 个 Chunk = 64 × 64 × 64 体素
体素类型：0 = 空气，1 = 泥土，2 = 石头
```

### 体素数据结构

```csharp
// 每个 Chunk 一个数组
byte[4096] voxels;

// 索引公式（Chunk 内局部坐标 0~15）
index = x + y * 16 + z * 16 * 16;
```

### 程序化生成公式

对每个世界坐标 `(x, z)`：

1. `height = PerlinNoise(x, z) * 20 + 30`（高度约 10~50）
2. `y <= height` → 实心（`y == height` 为泥土，`y < height - 3` 为石头）
3. `y > height` → 空气

**阶段 1 不使用 3D 洞穴噪声。**

### 网格生成（Naive 外露面剔除）

对每个实心体素，检查 6 个邻居：

- 邻居是空气 → 生成该面
- 邻居是实心 → 跳过

每个 Chunk 独立 Mesh + 一个 `MeshCollider`。

### 玩家

- 组件：`CharacterController`（高 2，半径 0.5）
- 重力：`(0, -9.81, 0)`
- 移动：水平 WASD；相机仅子物体负责 Pitch，玩家根物体仅 Yaw

### 挖掘流程

1. 相机 `Physics.Raycast`
2. 命中 Chunk 的 `MeshCollider`
3. 世界坐标 → Chunk 坐标 + 局部体素坐标
4. 体素设为 `0`（空气）
5. 标记 Chunk Dirty → 下一帧 `RebuildMesh`

### 跨 Chunk 挖掘（易出 Bug，规则写死）

体素局部坐标超出 `0~15` 时：

1. 计算相邻 Chunk 坐标
2. **两个 Chunk 的体素都要修改**
3. **两个 Chunk 都 Mark Dirty 并重建**

### 存档

- 只存：`(chunkX, chunkY, chunkZ, byte[4096])`（被玩家改过的 Chunk）
- 加载：先生成程序化地形 → 再用存档覆盖

### 第一阶段验收清单

| # | 测试 | 通过标准 |
|---|------|----------|
| 1 | 生成 | 进入游戏能看到连续地形，无大面积空洞 |
| 2 | 行走 | 能在地表行走，不穿地、不抖动 |
| 3 | 挖方块 | 左键能挖，挖处变空气 |
| 4 | 碰撞 | 挖过的坑能走进去，不卡进地里 |
| 5 | 边界 | 走到世界边缘被挡住或不会无限下落 |
| 6 | 存档 | 挖洞 → 退出 → 再进 → 洞仍在 |
| 7 | 压力 | 连续挖 100 个方块，不崩溃、不明显变卡 |

**7 条全部通过，才进入第二阶段。**

## 第二阶段：添加洞穴（仍平地）

在第一阶段代码稳定后，**只改生成逻辑**：

```csharp
// 在已判定为实心的体素上追加
if (3DNoise(x, y, z) > 0.6f)
    voxel = Air;
```

- 挖/网格/碰撞/存档逻辑**完全不动**

### 验收

- [ ] 能走进洞穴
- [ ] 在洞穴内挖壁不会崩溃或 Mesh 错乱

---

## 第三阶段：流式加载（仍平地）

- 世界从固定 4×4×4 扩展为「理论上无限」
- 只加载玩家周围 `3×3×3` 个 Chunk
- **卸载前**：若 Chunk 被修改过，必须先写入存档

### 验收

- [ ] 朝单一方向行走 500m，无重复加载、无丢洞
- [ ] 内存不会无限增长

---

## 第四阶段：小星球（最后才做）

**前置条件：前三阶段全部验收通过。**

### 做法（避免立方体球映射）

- Chunk 仍为**世界空间轴对齐**（与 Minecraft 相同）
- 实心判定改为：

```
density = planetRadius - |position - center| + surfaceNoise(position)
density > 0  → 实心
density <= 0 → 空气
```

- 重力方向：`down = normalize(center - playerPos)`
- CharacterController 的 Up 对齐 `-down`
- **星球半径先固定 100m**

### 验收

- [ ] 能绕球面行走，不会掉落
- [ ] 在球顶挖洞不会 Mesh 错乱
- [ ] 球面任意位置挖的洞都能正确存档/读档

---

## 已知现象与对策

| 现象 | 是否正常 | 处理方式 |
|------|----------|----------|
| 挖完上方方块悬空 | 正常 | 不做物理塌方（独立系统，后期可选） |
| 方块边缘有缝 | 可接受 | 后期 UV/顶点微调 |
| Chunk 边界挖洞 | 需严格处理 | 两个 Chunk 都改、都重建 |
| 存档体积增大 | 正常 | 只存有改动的 Chunk |

## 与 No Man's Sky 的对比

| 维度 | No Man's Sky | 本计划 |
|------|--------------|--------|
| 程序化 | 是（公式 + 噪声） | 是（噪声 + 体素） |
| 可行走 | 是 | 是 |
| 自由挖洞/挖穿 | 否 | **是** |
| 技术路线 | 高度图 / 公式网格 | **体素 + 程序化** |

## 一句话总结

**用「程序化 3D 方块体素 + 固定 Chunk + Naive 网格 + CharacterController」做平地原型，验收稳了再加洞穴、流式、星球。** 这是独立开发中成功率最高、Bug 最好查的路径。
